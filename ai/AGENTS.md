# ai/

> Python reinforcement learning package for Fenghua Mahjong.

## Overview

This directory contains the Python-side RL stack. Go remains the authoritative simulator; Python owns model definition, data loading, checkpointing, and training orchestration. The package now supports both a mock bridge for smoke tests and a real `ctypes` bridge to the Go c-shared library.

## Key Files

- **pyproject.toml** — Python package metadata and dependencies for the RL stack.
- **src/fh_mahjong_ai/config.py** — Dataclass configs for environment, model, training, advantage-weighted BC, discrete IQL, offline Q-learning, and self-play.
- **src/fh_mahjong_ai/action_catalog.py** — Python labels and family helpers for the Go bridge's fixed 204-action catalog, using the same backend tile-face order as `internal/rl/action.go`.
- **src/fh_mahjong_ai/mlflow_tracking.py** — Shared MLflow setup/logging helpers for training and inference/evaluation scripts.
  - Metric keys are sanitized before logging so nested report bucket names remain accepted by MLflow.
- **src/fh_mahjong_ai/checkpoint_manifest.py** — Loader/resolver for tracked best-checkpoint metadata in `ai/checkpoints/best-checkpoints.json`; binary checkpoint files stay outside git (single exception: the deployed champion under `checkpoints/deploy/`). Serving can resolve the classic current checkpoint with `current` and the Chongci current checkpoint with `current_chongci`.
- **src/fh_mahjong_ai/types.py** — Shared observation, transition, branch-evaluation, and bridge result types.
- **src/fh_mahjong_ai/bridge.py** — Abstract bridge contract, mock bridge, and `CtypesGoBridge` implementation for the Go RL library.
  - `MockMahjongBridge` retains the last emitted observation so `step()` validates actions against the real current legal-action mask instead of sampling a fresh one.
  - Bridges preserve `last_reset_result` so evaluation can count rounds that terminate during reset before the learning seat receives a decision.
  - `evaluate_branches()` asks the Go bridge to clone the current simulator state, apply candidate action ids, and finish each branch with deterministic heuristics; use this for exact same-state counterfactual label generation.
  - `CtypesGoBridge` decodes `round_outcome` / `terminal_outcome` protobuf messages into `StepResult.info` / `Transition.info`.
  - `CtypesGoBridge` owns the Go-side handle lifecycle and supports `close()`, context-manager usage, and best-effort cleanup in `__del__`.
- **src/fh_mahjong_ai/env.py** — Thin environment wrapper around the bridge.
- **src/fh_mahjong_ai/envpool.py** — Env-pool abstraction for lockstep-round collection: `GoEnvPool` (batched FFI over FHEnvPool*, flat float32/uint8 observation buffers decoded with np.frombuffer) and `InProcessEnvPool` (loops ordinary bridges; test/CPU-exactness path). `make_selfplay_pool()` builds the all-4 self-play EnvConfig and picks the implementation by bridge kind. Pools never self-reset a slot — the caller owns the seed schedule.
- **src/fh_mahjong_ai/model.py** — PyTorch policy/value/Q network for masked-action Mahjong decisions, defaulting to a Suphx-style no-pooling residual tile-plane encoder with an optional pooled ablation.
  - The Q path uses a Mortal-style dueling value/advantage head by default; channel attention is available as an explicit `ModelConfig(channel_attention=True)` ablation.
  - `infer_model_config(state_dict)` recovers a saved PolicyValueNet's ModelConfig (channels, residual blocks, head dims, pooling/attention/dueling flags) from tensor shapes, so checkpoint loaders never assume ModelConfig defaults.
  - The shared trunk also exposes default-off state and action-conditioned large-loss probability/severity auxiliary heads for Chongci tail-risk experiments; serving still selects actions from the masked policy logits.
- **src/fh_mahjong_ai/policies.py** — Random, torch-backed, and Q-margin guarded policy adapters; guarded evaluation chooses anchor/candidate actions from policy logits and uses the candidate Q head only as a confidence margin.
  - `TailConstrainedCandidatePolicy` lets a reward-trained candidate override the anchor only when candidate Q improves and an action-risk model predicts no large-loss probability increase over the anchor action, with optional tolerance and absolute risk ceiling.
  - `RiskGuardedPolicy` keeps the anchor action by default and only switches to a lower-risk legal action when an action-risk critic predicts the anchor action is risky and the substitute is close enough under anchor policy logits. Use `selection_mode="policy_nearest"` when auditing whether policy-preserving substitutes beat the legacy lowest-risk substitute ranking.
- **src/fh_mahjong_ai/serving.py** — Checkpoint-backed inference helpers and bridge smoke tests for serving actions while the Go bridge validates legality. `CheckpointPolicy.from_checkpoint` infers the network architecture from the checkpoint via `infer_model_config`, so promoted checkpoints may differ in depth/width from ModelConfig defaults.
  - `CheckpointPolicy.from_checkpoint(..., sample_temperature=T, sample_top_k=K, sample_action_family=F, seed=S)` can sample legal masked actions for dataset generation; keep the default `T=0.0` / `K=0` for greedy serving/evaluation. Family-scoped sampling only applies when every legal action belongs to that family, for example discard-only exploration rows.
  - Served actions expose `greedy_action_id`, `sampling_applied`, and `sampled_from_greedy` so mixed self-play can distinguish true exploration from sampled calls that matched the greedy anchor.
  - `CheckpointPolicy.evaluate_batch(planes, scalars, action_masks, chunk_size=256) -> (probs [N,204] float32, values [N] float32)` is the batch/deterministic sibling of `choose()` for the post-game review pipeline: no sampling, `torch.inference_mode`, softmax over legal actions only with exact zeros on illegal ones (mask applied both to model logits and post-softmax), and the same scalar zero-padding as `choose()`. Chunking is purely a memory knob — `evaluate_batch` output is chunk-size-invariant.
- **src/fh_mahjong_ai/data.py** — Episode grouping (`split_episodes`), episode-safe train/validation splitting, terminal-reward backfill (`backfill_returns`), `steps_to_done` utilities, and `placement_shaped_returns()` which converts the per-seat terminal-reward vector into rank-based placement values (ranks 1-4 map to a configurable table, ties averaged) for placement-aware reward shaping.
- **src/fh_mahjong_ai/evaluate.py** — Offline action-agreement scoring with action-family breakdowns, duplicate-seat evaluation, and online live-play evaluation against the heuristic baseline. `reward_summary()` reports `sem` and `ci95` (standard error and 95% CI of mean reward); online and duplicate-seat reports expose `mean_reward_sem`/`mean_reward_ci95` so checkpoint comparisons can use CI-separated promotion gates.
  - Online reports include precise mean/sum reward, reward distribution, action-family rates, and duplicate-seat `seat_summary`.
  - Online/duplicate evaluation accepts `match_mode="chongci"` plus Chongci score/hand-cap config; Chongci reports `positive_reward_rate` as the final-match net-positive metric while keeping `win_rate` as a backward-compatible reward-positive alias.
  - Online evaluation sums per-step rewards per episode through `episode_reward_vector`, so Chongci dense step rewards recover the final match outcome.
  - `evaluate_policy_online()` / `evaluate_duplicate_seats_policy()` support non-model policy adapters such as Q-margin and risk guards while preserving the same duplicate-seat metrics; guarded-policy reports include generic intervention summaries by source and action family.
  - Duplicate-seat evaluation now reports `mean_placement` (mean rank among the four seats, 1 = best) alongside `mean_reward` (net score); use `mean_placement` as the primary objective when evaluating GRP-shaped PPO checkpoints and compute an anchor baseline placement too.
- **src/fh_mahjong_ai/reward_calibration.py** — Offline Q/value calibration diagnostics against discounted terminal round payout targets, with action-family and target-sign breakdowns.
  - When `--large-loss-threshold` is supplied, reward calibration also reports large-loss probability/severity calibration for target-side risk experiments. It defaults to action-conditioned risk heads when available.
  - Large-loss calibration includes per-action-family probability/severity diagnostics so tail-risk failures can be separated for discard, chii, pon, kan, win, pass, haitei, and unknown action ids.
- **src/fh_mahjong_ai/global_ev.py** — Visible-state global expected-value predictor for Chongci-style match outcomes. It trains a separate value model from observation tensors to final acting-seat terminal reward and reports against a constant train-mean baseline before using the signal for policy work. `global_ev_targets()` accepts `reward_shaping="placement"` so the global EV value function can be trained on rank-based placement EV; IQL `--target-mode global_ev_td` then bootstraps placement-aware Q targets.
  - `ActionGlobalEVNet` supports `EV(state, action_id)`. `fh-mj-train-global-ev --branch-cf-action-targets` expands exact branch-CF preferred/avoided branch rewards into action-conditioned EV samples.
- **src/fh_mahjong_ai/global_ev_diagnostics.py** — First-divergence diagnostics that score paired trace anchor/candidate observations with a frozen global EV model and report predicted-vs-actual reward deltas by action-family pair.
  - Also includes exact branch-CF calibration helpers for action EV, reporting preferred-action rate, reward-gap-weighted preferred rate, and simple guard-preflight margins.
- **src/fh_mahjong_ai/paired_trace_delta.py** — Direct paired-trace candidate-anchor reward-delta model and diagnostics. Use it after action-EV regressors overfit source windows: it predicts the final reward delta from the shared first-divergence visible scalars/context plus both divergent action ids instead of assigning absolute EV to each action separately.
  - The optional sequence model consumes compact visible pre-divergence prefix rows from paired-trace reports. Keep this diagnostic-only until it passes independent holdout preflight; do not use it for guarded serving from train-window gains alone.
- **src/fh_mahjong_ai/risk_filter.py** — Utilities for extracting high-risk first-divergence cases from paired trace reports and applying per-transition sample weights plus optional pairwise preferred/avoided action labels and reward-delta targets. The loader must use each report's stored `left_label` / `right_label` when resolving reward and outcome keys, because Chongci diagnostics often use named candidates such as `candidate_t054_w075` rather than the generic `candidate`.
- **src/fh_mahjong_ai/paired_trace.py** — Paired online trace diagnostics for comparing two checkpoints on the same seed/seat schedule and recording first action-divergence contexts.
  - Observation summaries name Chongci score-pressure scalars for risk reports: leader pressure, large-loss safety margin, own bust safety, and opponent large-loss pressure.
  - Paired trace summaries include `counterfactual_supervision`, which converts first-divergence outcome differences into preferred/avoided action-family counts and tags new deal-in / new large-loss cases before training on paired labels.
  - Paired trace comparison can resume from existing seed/seat pairs and skip completed entries, so long tensor-bearing trace jobs can be checkpointed instead of writing only at the end.
  - `--max-divergences` can persist additional aligned action disagreements after the first divergence. Treat those later rows as risk-calibration evidence only; after the first different action, paired trajectories are no longer guaranteed same-state counterfactuals.
  - Reports include compact visible `pre_divergence_sequence` rows for sequence-aware paired-delta diagnostics. These rows must remain reward-free and hidden-info-free.
- **src/fh_mahjong_ai/paired_trace_q_diagnostics.py** — Q/policy ranking diagnostics for tensor-bearing paired traces. Use it after a live smoke/gate reject to check whether a checkpoint's Q head ranks realized preferred first-divergence actions above avoided actions before allowing another policy-improvement update.
- **src/fh_mahjong_ai/near_state_counterfactuals.py** — Filters tensor-bearing paired traces into stricter discard-vs-discard near-state cases. It requires both chosen discard actions to be legal in both recorded observations plus bounded visible-scalar and action-mask distance; use it for risk data mining, not direct checkpoint promotion.
- **src/fh_mahjong_ai/branch_counterfactuals.py** — Exact Go-branch counterfactual helpers that select best/worst branch outcomes from `evaluate_branches()` and build pairwise NPZ arrays for IQL auxiliary training.
  - Existing broad branch-CF generation defaults to discard-only labels. Sampled-vs-greedy branch-CF generation can pass all action families and records greedy/sample action ids for diagnostics.
- **src/fh_mahjong_ai/branch_cf_calibration.py** — Diagnostics for exact branch-counterfactual shards. It reports whether policy logits, Q values, and optional action-risk heads rank the preferred branch action above the avoided action before using branch labels for more training.
  - It also provides failure-slice summaries for Q/policy misranked branch rows, including action-pair counts, high-gap examples, and visible scalar summaries.
- **src/fh_mahjong_ai/buffer.py** — Object and array-backed replay buffers with terminal-reward-aware value targets plus next-observation/reward/done fields for TD learning. Both buffers accept `reward_shaping="placement"` (plus `placement_values`) to return rank-based placement returns instead of raw per-seat net score.
  - `ArrayReplayBuffer` can also sample from BC-only arrays that omit next-state TD fields.
- **src/fh_mahjong_ai/storage.py** — Checkpoint, JSONL, and sharded NumPy transition persistence helpers.
  - `read_transitions()` accepts either JSONL or a NumPy shard directory containing `manifest.json`.
  - `read_transition_arrays(..., keys=...)` can load only the arrays needed by a trainer.
  - `ShardedTransitionWriter` supports incremental direct-to-shard generation without a temporary JSONL file.
  - Sharded transition data preserves `steps_to_done` and compact terminal outcome fields for future offline diagnostics.
  - Mixed self-play shards additionally preserve numeric `policy_source_ids` and optional `policy_values`; the dataset manifest maps source ids to checkpoint/random/heuristic seat policies.
- **src/fh_mahjong_ai/trainer.py** — Self-play collection, behavior-cloning, advantage-weighted BC, discrete IQL, and conservative offline Q-learning trainer utilities.
  - Discrete IQL can optionally use a frozen external action-risk checkpoint as a training-side policy regularizer. This penalizes policy probability on legal actions above a risk threshold, optionally scoped to one action family such as `discard`.
  - Discrete IQL also supports `large_loss_bc_weight`, an explicit tail-preserving behavior-cloning constraint applied only to transitions whose terminal return is at or below `large_loss_threshold`.
- **src/fh_mahjong_ai/ppo.py** — Online self-play PPO: `PPOConfig`, `RolloutBatch`, `masked_policy_distribution`, `compute_gae`, `ppo_update` (masked clipped surrogate + value + entropy), `collect_rollouts` (on-policy; learning seat samples, frozen-anchor opponents, torch seeded per match for reproducibility), and `train_ppo` (warm-start anchor policy+value → collect → GAE → update → periodic duplicate-seat CI gate → checkpoint). `PPOConfig.num_workers` enables parallel rollout collection; `1` keeps the sequential collector. `default_num_workers()` gives a core-aware default (rollout throughput is CPU-core-bound, ~380MB/worker so RAM is not the limit; scales near-linearly to ~8, knee near 16 on a 24-core box); it counts CPUs available to the process (`sched_getaffinity` + cgroup CPU-quota clamp), not the host total. The self-play/oracle CLIs default `--num-workers` to `min(default_num_workers(), --matches-per-iter)` so short runs don't spawn idle workers. This is the first ONLINE/on-policy trainer — it can surpass the offline/heuristic ceiling because it learns from its own explored actions, unlike BC/IQL. `train_ppo` trains against an opponent pool (anchor + past-learner snapshots) controlled by `--pool-max-size` / `--pool-snapshot-interval`; `pool_max_size=1` (default) is the single-anchor-only behavior. Opponents are sampled per match/seat deterministically from the pool; `pool_size` is logged to MLflow each iteration. `PPOConfig.grp_checkpoint` / `--grp-checkpoint` replaces the per-hand score reward with a GRP (GlobalEVNet) placement-value delta: each non-terminal step receives `g_{t+1} - g_t` and the terminal step receives `realized_placement - g_last`, where `g` is the frozen GRP's predicted placement EV. The GRP is trained offline via `fh-mj-train-global-ev --reward-shaping placement` on anchor trajectories and stays frozen during PPO; the parallel collector ships the frozen GRP to workers so pool-composition changes take effect without reloading. `grp_checkpoint=None` (default) leaves the reward unchanged as per-hand score.
- **src/fh_mahjong_ai/batched_selfplay.py** — Batched self-play collector: one pool call + ONE batched model forward per round (GPU-friendly), per-match numpy RNG sampling (`sample_masked_action`; no global torch RNG), δ feature-dropout with the same per-match mask stream as the process collector, per-seat-contiguous emission flushed in SEED ORDER (makes per_row-CPU output invariant to slot count — tested as full-array equality). `PPOConfig.collector="batched"` + `pool_slots` select it in `train_selfplay_oracle`; `"process"` remains the default until the throughput/quality gate passes.
- **src/fh_mahjong_ai/parallel_rollouts.py** — `ParallelRolloutCollector` parallelizes full-match self-play rollouts across a persistent spawn-context pool of CPU-inference workers, concatenates their batches, and leaves the PPO update in the main process. It deterministically matches the sequential collector over the same seeds. The collector ships the full opponent pool to workers each iteration so pool composition changes take effect immediately.
- **src/fh_mahjong_ai/scripts/selfplay_smoke.py** — Mock-bridge smoke runner that exercises the package end to end.
- **src/fh_mahjong_ai/scripts/generate_data.py** — CLI: generate heuristic trajectories → JSONL or sharded NumPy plus dataset manifest via the Go bridge (or mock fallback).
  - `--match-mode chongci` forwards Chongci config to the Go bridge for multi-hand heuristic trajectory generation.
  - `--chunk-size` bounds each bridge export request and preserves globally unique `episode_index` values across chunks.
  - `--format npz-shards` writes generated chunks directly to sharded NumPy storage.
  - Long generation jobs print per-chunk progress and include elapsed seconds in the dataset manifest.
- **src/fh_mahjong_ai/scripts/generate_selfplay.py** — CLI: generate Mortal-style mixed self-play trajectories where selected seats are controlled by checkpoint/random Python policies and the Go bridge auto-plays heuristic seats.
  - `--seat-policy` supports `seat=checkpoint:/path/to.pt`, `seat=random`, and `seat=heuristic`; omitted seats default to heuristic.
  - Checkpoint seat policies may append per-seat sampling overrides such as `3=checkpoint:/path/epoch_001.pt?temperature=0.75&top_k=3&sample_family=discard`, allowing greedy anchor seats and one controlled exploration seat in the same table.
  - `--checkpoint-temperature T` samples checkpoint policy logits for exploration data while preserving deterministic seeding and recording the temperature in the dataset manifest. The default `0.0` remains greedy.
  - `--checkpoint-top-k K` restricts checkpoint sampling to the top-K legal checkpoint actions when temperature sampling is enabled; use it for controlled self-play exploration that avoids low-probability legal actions.
  - `--checkpoint-sample-action-family F` limits checkpoint sampling to decisions where all legal actions are in family `F`; per-seat `sample_family` overrides this global default.
  - Output uses the same JSONL or sharded NumPy transition format as heuristic generation, with per-transition policy source ids for later analysis.
- **src/fh_mahjong_ai/scripts/dataset_diagnostics.py** — CLI: summarize operation-level replay coverage before training, including policy-source mix, action-family distribution, final acting-seat return, large-loss coverage, deal-in/win/draw outcomes, Chongci score-pressure buckets when 58-scalar observations are present, and sampled-vs-greedy exploration coverage when policy sampling arrays exist.
- **src/fh_mahjong_ai/scripts/replay_policy_diagnostics.py** — CLI: compare an anchor checkpoint, a candidate checkpoint, and stored replay actions on existing datasets before live evaluation. Use it to reuse previous self-play / branch-derived replay by measuring candidate-vs-anchor divergence, action-family drift, policy-source slices, and return buckets.
- **src/fh_mahjong_ai/scripts/generate_branch_counterfactuals.py** — CLI: collect states from checkpoint/random self-play seats, evaluate legal discard branches from the exact cloned Go state, and write direct pairwise NPZ shards for `fh-mj-train-iql --pairwise-data`.
  - Use this after paired-trace coverage is too sparse: it labels alternate legal discards from one state directly instead of waiting for two policies to diverge on the same decision.
  - The default branch mode stops at the next round end, which is the practical label for Chongci branch-CF data. Use `--branch-through-match-end` only for expensive full-match ablations, and include `--progress-every N` plus `--max-elapsed-seconds S` on remote probes so long branch rollouts are observable.
- **src/fh_mahjong_ai/scripts/generate_sampled_branch_counterfactuals.py** — CLI: run a checkpoint with seeded top-k sampling, branch-evaluate the greedy anchor action versus the sampled action whenever they differ, and write exact same-state pairwise shards for `fh-mj-train-iql --pairwise-data`.
  - Use this after top-k sampled self-play improves exploration diversity but broad IQL on the sampled data fails. It targets the actual sampled-vs-greedy divergences instead of applying another global replay update.
  - For Chongci probes, keep `--max-steps-per-episode 0` unless deliberately testing truncation; this lets the Go bridge use its match-mode default and avoids false zero-reward `match_truncated` smoke reports.
- **src/fh_mahjong_ai/scripts/generate_targeted_branch_counterfactuals.py** — CLI: replay an anchor checkpoint to seed/seat/decision targets from paired-trace or action-EV diagnostic reports, evaluate exact legal branches at those live Go states, and write pairwise NPZ shards.
  - Use this after guard preflight false positives identify high-impact contexts that broad branch-CF data does not cover. Replay one learning seat at a time so the Go state matches the original paired trace.
- **src/fh_mahjong_ai/scripts/branch_cf_calibration.py** — CLI: evaluate a checkpoint on exact branch-counterfactual pairwise shards, logging preferred-action rates for policy logits, Q values, optional risk heads, and policy-top-k proposal/rerank diagnostics. Use this after a branch-CF training run fails the duplicate gate to determine whether the model failed to fit branch labels, fitted labels that do not transfer, or cannot even propose the preferred branch action.
- **src/fh_mahjong_ai/scripts/branch_cf_diagnostics.py** — CLI: write detailed branch-CF failure-slice reports, especially high-reward-gap rows where Q or policy ranks the avoided action above the preferred exact branch label.
- **src/fh_mahjong_ai/scripts/branch_cf_guard_diagnostics.py** — CLI: preflight a risk-guard configuration against exact branch-CF labels before running a duplicate-seat gate. It reports rescues, harms, unlabeled switches, known reward-gap deltas for guard interventions, and oracle preferred-branch upper bounds under relaxed policy-logit caps.
- **src/fh_mahjong_ai/scripts/targeted_branch_cf_diagnostics.py** — CLI: summarize targeted branch-CF proposal quality by comparing paired-trace left/right actions against exact preferred/avoided branch labels. Use it when targeted action-EV guards fail and the next question is whether the candidate proposes good branches at all.
- **src/fh_mahjong_ai/scripts/global_ev_diagnostics.py** — CLI: score paired-trace first divergences with a frozen global EV checkpoint. Use it after a `global_ev_td` or other policy probe loses a smoke gate to identify whether global EV predicted the harmful divergence and which action-family pairs were mis-scored.
- **src/fh_mahjong_ai/scripts/action_ev_branch_cf_calibration.py** — CLI: evaluate an action-conditioned global EV checkpoint against exact branch-CF preferred/avoided labels before using it for any guard or rerank experiment.
- **src/fh_mahjong_ai/scripts/convert_data.py** — CLI: convert JSONL transition data into sharded NumPy replay storage.
- **src/fh_mahjong_ai/scripts/train_bc.py** — CLI: behavior cloning training with deterministic episode-level train/validation split, validation agreement reporting, checkpointing, and resume support.
- **src/fh_mahjong_ai/scripts/train_awbc.py** — CLI: advantage-weighted behavior cloning, intended as the first conservative offline RL improvement over a BC warm-start.
- **src/fh_mahjong_ai/scripts/train_iql.py** — CLI: discrete implicit Q-learning style offline RL with MC terminal-return targets by default, optional TD Q targets, expectile value learning, advantage-weighted policy updates, optional CQL penalty, BC regularization, pairwise divergence preference loss, and optional transition limiting for memory control.
  - `--target-mode global_ev_td --global-ev-checkpoint PATH` uses a frozen visible-state global EV model for Bellman targets: immediate reward plus discounted next-state global EV. This is the Mortal/Suphx-style bridge between a calibrated outcome predictor and policy/Q learning.
  - `--reward-shaping placement` (plus optional `--placement-values` for the 4 rank values) replaces the raw per-seat net-score MC return target with rank-based placement value. Combine with a placement-trained GlobalEV (`fh-mj-train-global-ev --reward-shaping placement`) under `--target-mode global_ev_td` for placement-aware bootstrapped targets. Treat it as an isolated reward-target ablation: train on the same data as the raw baseline and promote only on the duplicate-seat CI gate.
  - `--critic-only` freezes the policy-selection path and trains only `q_head.*` / `value_head.*`; use it for Q-ranking diagnostics before allowing a failed reward-learning branch to influence policy logits.
  - `--policy-head-only` freezes the encoder and critics while training only `policy_head.*`; use it only for constrained exact-branch policy fixes that have passed Q-ranking preflight.
  - Repeat `--data` to train from multiple datasets, for example existing heuristic shards plus new mixed self-play shards. The trainer samples across datasets through a composite replay buffer without rewriting the source datasets.
  - `--large-loss-weight` upweights losses for transitions whose terminal return is at or below `--large-loss-threshold`; use it for explicit Chongci high-risk-state ablations.
  - `--risk-trace-report` upweights transitions matching paired-trace first-divergence risk cases when dataset start seeds are supplied through `--risk-trace-dataset-start-seed`.
  - `--pairwise-replay-multiplier` also repeats rows loaded through direct `--pairwise-data`, which is required when exact branch-CF shards are much smaller than the main mixed self-play replay.
  - `--pairwise-data-min-reward-gap` filters direct `--pairwise-data` rows by `pairwise_reward_delta_targets`; use it after broad branch-CF distillation overfits exact labels but damages live Chongci play.
  - `--policy-kl-anchor-checkpoint` plus `--policy-kl-weight` regularizes the trained masked policy distribution toward a frozen anchor policy. This is the preferred safety control before retrying policy-side branch-CF distillation.
  - `--risk-trace-filter-datasets` keeps the first `--data` input as the normal anchor/base replay source, then filters later risk-trace datasets down to exact matched first-divergence rows plus `--risk-trace-context-radius` same-episode/same-seat decision-index context.
  - `--risk-trace-counterfactual-labels` broadens IQL pairwise supervision to paired-trace first-divergence counterfactual labels above `--risk-trace-min-counterfactual-reward-gap`, matching the risk-critic label source while still requiring exact seed/seat/decision/action replay matches.
  - `--pairwise-weight` adds a direct policy-logit margin loss that prefers the paired-trace anchor action over the candidate action on matched high-risk first-divergence rows; `--pairwise-q-weight` applies the same preference to the Q head; `--pairwise-replay-multiplier` repeats those sparse rows into an auxiliary replay source.
  - `--pairwise-data` adds direct tensor-bearing paired-trace shards as auxiliary replay. These rows get zero normal IQL sample weight and only contribute preferred/avoided pairwise margin losses, so they do not behavior-clone the avoided action.
  - `--pairwise-reward-delta-weight` and `--pairwise-reward-delta-margin-scale` make pairwise IQL tail-aware by using `pairwise_reward_delta_targets` to increase relative row weight and required margin for larger counterfactual reward gaps.
  - `--large-loss-aux-weight` and `--large-loss-severity-weight` train target-side tail-risk heads from terminal returns without changing deployed action selection; `--large-loss-aux-detach` trains them from detached trunk features for diagnostic/no-policy-gradient ablations.
  - `--external-risk-checkpoint` plus `--external-risk-policy-weight` uses a frozen action-risk critic as a policy regularizer during IQL training. Prefer family-scoped first runs such as `--external-risk-policy-family discard`; this is the replacement path after serving-time risk guards failed independent duplicate gates.
  - `--large-loss-bc-weight` adds a policy-only preservation term on large-loss transitions. Use it with `--large-loss-threshold` when a candidate improves EV but regresses large-loss rate.
- **src/fh_mahjong_ai/scripts/train_global_ev.py** — CLI: train the separate visible-state global EV predictor on transition shards, using final acting-seat terminal reward as the label and reporting validation MAE/RMSE/correlation against a train-mean baseline. `--reward-shaping placement` (plus optional `--placement-values`) trains the predictor on rank-based placement EV instead of raw net-score EV.
  - `--action-conditioned` trains `EV(state, action_id)` instead of state-only EV, which is required for same-state first-divergence guard/rerank diagnostics.
  - `--branch-cf-action-targets` expands exact branch-CF preferred/avoided branch rewards into action-conditioned targets.
  - `--branch-cf-pairwise-weight` adds an explicit preferred-action-above-avoided-action margin loss for branch-CF action-EV training. Use this after branch reward regression ranks exact labels but still fails paired-trace guard preflight.
- **src/fh_mahjong_ai/scripts/train_pairwise_delta.py** — CLI: train the direct paired-trace reward-delta predictor from one or more train reports and evaluate named report splits. This is diagnostic-only until it passes holdout-only paired-trace preflight; it should be preferred over more action-EV coefficient sweeps when absolute action values fail cross-window holdouts.
  - `--sequence-model` uses the visible pre-divergence sequence encoder and should be compared against the scalar/action MLP on source-heldout paired-trace reports before any promotion attempt.
  - `--source-balanced-batches` and `--worst-source-loss-weight` are for source-robust sequence scorer experiments after a model passes one heldout source window but fails a fresh independent source. Use them to change the training objective, not to tune serving thresholds.
- **src/fh_mahjong_ai/scripts/train_branch_preference_policy.py** — CLI: train policy/Q heads to put exact branch-CF preferred actions into the checkpoint's top-k proposals. It initializes from an anchor checkpoint, freezes the shared encoder by default, and supports anchor KL regularization. Use this after targeted branch-CF diagnostics show the candidate rarely proposes exact preferred branches.
- **src/fh_mahjong_ai/scripts/train_action_risk.py** — CLI: train action-conditioned large-loss risk heads from saved transition shards with balanced positive/negative batches.
  - Use this as a calibration-only path when IQL auxiliary training is active but large-loss AUC remains near random; it optimizes the observed dataset action's risk probability and severity directly.
  - `--paired-trace-report` adds counterfactual first-divergence supervision: the risk head must rank the worse candidate action above the anchor action and fit the reward-delta severity target on matched seed/seat/decision rows.
  - `--paired-trace-counterfactual-labels` broadens paired supervision from only large-loss/worst-delta cases to all first-divergence reward-gap labels above `--paired-trace-min-reward-gap`; run a match-count smoke before training because shard coverage can still be sparse.
  - `--target-mode score_pressure` expands the terminal large-loss target with visible Chongci match-pressure context from scalars 42-57, so near-large-loss score states with negative final outcomes can train the risk critic before they cross the hard tail threshold.
  - `--target-mode discard_later_pressure` keeps terminal large-loss labels but adds positives only for discard actions followed by same-seat visible Chongci pressure within `--discard-later-window`, focusing the next risk experiment on the discard-dominated calibration failure.
  - `--target-mode discard_future_outcome` avoids pressure-proxy labels and adds positives for recent same-seat discard actions before actual bad terminal outcomes, including deal-in with non-positive final reward or large-loss final reward.
  - `--target-mode future_outcome_context` is the richer critic-side target for the next branch: it labels recent same-seat actions before actual bad terminal outcomes and scales credit by visible score pressure plus action family, instead of supervising only first-divergence or discard-only rows.
  - `--target-mode family_future_outcome_context` separates discard hindsight from chii/pon/kan/pass/haitei hindsight before actual bad outcomes; use it when broad family credit improves calibration but still leaves serving-time candidate filters too blunt.
  - `--family-balance-strength` and `--family-weight-clip` apply optional action-family-balanced loss weights while preserving stored `sample_weights`, so discard-heavy datasets do not fully dominate risk calibration.
- **src/fh_mahjong_ai/scripts/train_offline_q.py** — CLI: conservative masked-action offline Q-learning with optional BC warm-start.
- **src/fh_mahjong_ai/scripts/evaluate.py** — CLI: evaluate a checkpoint offline (action agreement) and/or online (live play).
  - Offline action-agreement inference is batched; tune `--offline-batch-size` for GPU memory/throughput.
  - `--match-mode chongci` forwards Chongci settings into online and duplicate-seat evaluation.
  - When `--max-steps-per-episode` is unset, the bridge decision cap defaults per mode: 256 (classic, via `EnvConfig`) or 4000 (chongci, matching `fh-mj-train-ppo`). A full chongci match needs ~1500 decisions, so the classic 256 default would truncate every match; the per-mode default lets matches reach `PHASE_MATCH_END` and report real standings. An explicit flag always wins.
  - `--sample-temperature T --sample-top-k K --sample-action-family F --sample-seed S` (requires `--duplicate-seats`) routes decisions through the SERVING sampler (`CheckpointPolicy` via `policies.SampledServingPolicy`), so a deployment temperature sweep measures exactly what production ships; seeded per seat, sampling config recorded under `report["sampling"]`. Default `T=0` keeps the greedy model path byte-identical.
- **src/fh_mahjong_ai/scripts/evaluate_guarded.py** — CLI: evaluate a candidate reward/Q checkpoint behind a promoted anchor policy, sweeping one or more minimum Q-margin thresholds.
- **src/fh_mahjong_ai/scripts/evaluate_risk_guarded.py** — CLI: evaluate an action-risk checkpoint as a conservative guard around a promoted anchor policy, sweeping anchor-risk thresholds while preserving Go legality validation. `--selection-mode policy_topk_risk --policy-top-k N` reranks only the anchor policy's top-N legal actions by risk and is the live counterpart to branch-CF proposal/rerank diagnostics.
- **src/fh_mahjong_ai/scripts/evaluate_tail_constrained.py** — CLI: evaluate a reward-trained candidate behind an anchor policy with an explicit no-worse-large-loss-risk constraint from an action-risk model. Use this after pairwise-margin IQL improves EV but regresses tail risk.
- **src/fh_mahjong_ai/scripts/reward_calibration.py** — CLI: report Q/value calibration against discounted terminal payout targets before promoting reward-trained checkpoints.
  - `--large-loss-threshold` enables auxiliary large-loss calibration metrics, including probability Brier/AUC and severity error; `--large-loss-risk-mode` can force action-conditioned or legacy state-only risk calibration.
- **src/fh_mahjong_ai/scripts/paired_trace.py** — CLI: run paired checkpoint traces over duplicate seed windows and save reward-delta, divergence, and context-bucket diagnostics.
  - `--incremental-report-interval` writes resumable partial reports during long runs; `--resume` reuses existing `--report-output` pairs and skips completed seed/seat entries.
  - `--include-action-scores` adds compact top masked policy-logit and Q-value diagnostics to each recorded step; use this for first-divergence analysis before adding another reward/risk objective.
  - Paired reports include `pre_divergence_context`, a reward-free scalar summary of action-family history and visible scalar deltas before the first divergence. Use this for trajectory-context action-EV experiments.
- **src/fh_mahjong_ai/scripts/paired_trace_q_diagnostics.py** — CLI: score a checkpoint's policy logits and Q values on tensor-bearing paired-trace first-divergence labels. Prefer this before training from fresh exploration data again; if Q cannot rank anchor/preferred actions correctly on failed smoke rows, freeze or strengthen the policy path and fix Q/value learning first.
- **src/fh_mahjong_ai/scripts/extract_near_state_discards.py** — CLI: produce JSON reports of high-confidence near-state discard-vs-discard cases from paired traces. Prefer this before training on later aligned disagreements, because it filters out rows where the alternate discard was not legal in both observations.
- **src/fh_mahjong_ai/scripts/build_counterfactual_risk_data.py** — CLI: convert tensor-bearing paired trace first-divergence labels into a tiny sharded NPZ dataset with direct preferred/avoided action-risk supervision. Like `risk_filter.py`, it must honor each report's stored `left_label` / `right_label` instead of assuming generic `anchor` / `candidate` reward keys. Use `--preferred-policy <label>` when building anchor-preserving shards, for example keeping only rows where `promoted_anchor` beat a rejected candidate. Use `--preferred-action-family` / `--avoided-action-family` for narrow failure-slice shards such as discard-vs-discard policy-preservation cases. Use `--training-target-policy preferred` only for teacher-policy distillation shards; default `avoided` preserves the risk/negative-example behavior. Use `--divergence-source later|all` only for broader aligned-disagreement risk calibration; the default `first` remains the strict same-state counterfactual dataset path.
- **src/fh_mahjong_ai/scripts/build_paired_trace_action_ev_data.py** — CLI: convert tensor-bearing paired trace first-divergence outcome deltas into the branch-action EV NPZ schema (`branch_preferred_rewards` / `branch_avoided_rewards`). Use this when same-state branch-CF labels rank local alternatives but fail full paired-trace preflight; it trains from actual anchor-vs-candidate match reward differences instead of only best/worst branch rollouts. Keep `--divergence-source first` for strict first-divergence evidence; later/all rows are aligned by trace index only. `--include-trajectory-context` appends paired-trace `pre_divergence_context` scalars and requires diagnostics/evaluation scripts that preserve the wider scalar shape.
- **src/fh_mahjong_ai/scripts/serve_policy.py** — CLI: lightweight JSON HTTP policy server. It returns an `action_id`; callers must still apply Go-side action decoding/validation before mutating game state.
  - `--sample-temperature/--sample-top-k/--sample-action-family/--sample-seed` serve softened (sampled) actions for human-facing play; `/healthz` reports the active sampling config, and `POST /reload` PRESERVES it (a hot-swap never silently reverts to greedy). Swept 2026-07 on the deep4 student: T≤0.7 with top-k 3 + discard-only is cost-free vs greedy (paired vs anchor +0.29..+0.31, large_loss ≤0.127); T=1.0 degrades tail risk (large_loss 0.158) — deploy T=0.7 top-k 3 discard-only.
  - `POST /evaluate {"observations": [{"seat": int, "planes": [...], "scalars": [...], "action_mask": [...]}]}` batches `CheckpointPolicy.evaluate_batch` for the Go post-game review pipeline (`internal/review/client.go`). Response: `{"results": [{"probs": [204 floats], "value": float}, ...], "checkpoint_path": str, "checkpoint_step": int}`, results in request order, `probs` dense length-204 with exact zeros on illegal actions, deterministic (no sampling regardless of the server's `--sample-*` flags). Requests over `MAX_EVALUATE_BATCH` (1024 observations) are rejected with 400 `{"error": ...}`, same as any other malformed payload — the Go client chunks at 256 so it never trips this cap. An observation whose `action_mask` has no legal action is also rejected with 400 `{"error": "observation <i> has no legal actions"}` instead of returning NaN probs (mirrors the `choose()` guard).

## Architecture Notes

- Use uv for all Python package, environment, and command execution work: `uv sync --project ai --extra dev`, then `uv run --project ai ...`.
- Avoid non-uv package or environment commands in this repo.
- `ai/.python-version` pins the uv-managed Python interpreter used by this package.
- Python support is pinned to uv-managed CPython 3.12 for the AI package.
- `EnvConfig` defaults now match the real Go bridge (`39 x 42 x 1` observations, 58 scalars, 204 discrete actions).
- Legacy 42-scalar checkpoints are padded in `storage.load_checkpoint()` so old policy weights can load while new Chongci match-context scalar weights start at zero.
- `EnvConfig.match_mode` can be `classic` or `chongci`; Chongci adds starting-score, bust-threshold, and max-hands fields passed through to protobuf.
- `MockMahjongBridge` remains available for smoke tests, but `bridge_kind="go"` is now the default for real bridge work.
- The Python package stays compatible with Python 3.9 by avoiding `dataclass(slots=True)` in the scaffold types/configs.
- All action selection assumes the fixed 204-action catalog supplied by the Go bridge.
- Dataset generation writes a manifest next to each JSONL file or shard directory with seed range, policy source, bridge kind, git commit, action-space size, and observation dimensions.
- Large Go-bridge exports should use chunked generation instead of one large protobuf response; the CLI defaults to `--chunk-size 1000`.
- Large generated datasets should prefer `fh-mj-generate-data --format npz-shards` so the pipeline avoids a huge temporary JSONL file.
- Large training datasets can be converted with `fh-mj-convert-data` to sharded NumPy storage; training/evaluation CLIs accept the shard directory as `--data`.
- Sharded NumPy datasets use array-backed replay for BC/AWBC/IQL/offline-Q and streaming batches for offline evaluation to avoid materializing every row as a Python object. BC and AWBC training load only current-observation/action/return arrays to keep 50k+ datasets within WSL memory; IQL/offline-Q need next-state arrays and may use transition limits for memory control.
- New sharded datasets preserve `decision_indices` and `sample_weights` so paired-trace first-divergence cases can map back into training rows; older shards without decision indices fall back to seed/seat/action matching when risk filtering is explicitly requested.
- IQL can mix repeated `--data` inputs directly; this is the preferred way to reuse older heuristic datasets alongside newer mixed self-play datasets.
- IQL supports default-off large-loss utility shaping through `--large-loss-threshold` plus `--large-loss-penalty`. Use it only as an explicit Chongci reward-learning ablation and keep promotion decisions based on duplicate-seat EV/positive-rate/large-loss gates, not training loss.
- IQL also supports default-off high-risk transition weighting through `--large-loss-weight`; it reweights Q/value/policy/BC/CQL losses without changing the sampled dataset or deployed policy rule.
- IQL risk-trace weighting consumes paired trace reports, maps report seeds to dataset `episode_index` using provided dataset start seeds, applies per-transition `sample_weights`, and can attach pairwise preferred/avoided action ids for the optional divergence preference loss.
- IQL large-loss auxiliary training predicts both probability of crossing `--large-loss-threshold` and severity beyond that threshold from the shared trunk. New checkpoints train action-conditioned risk over the 204-action catalog and gather the observed dataset action; keep both weights default-off and treat shared-gradient variants as representation-shaping ablations unless duplicate-seat evaluation improves. Use `--large-loss-aux-detach` when the goal is calibration/diagnostics without changing trunk gradients.
- Balanced action-risk training is separate from IQL promotion. It exists to calibrate `P(large loss | visible state, action)` before any serving-time guard is considered. Paired trace action-risk runs are also calibration experiments: they can reject or accept a risk critic, but they do not promote the underlying policy checkpoint by themselves.
- The score-pressure action-risk target is a diagnostic/critic target, not the promotion objective. Use it to rank risky visible match states and validate with independent calibration before using it in any guard.
- IQL/evaluation CLIs expose model-size flags such as `--model-channels`, `--model-residual-blocks`, and `--model-channel-attention` for controlled architecture ablations. `--partial-init-checkpoint` may be used for explicit ablations that add compatible layers, such as more residual blocks with the same channel width. Record these flags in MLflow and report outputs whenever a non-default checkpoint is trained.
- BC training writes a JSON report with train/validation transition counts, per-epoch losses, validation exact agreement, top-3 agreement, and action-family agreement.
- MLflow tracking is opt-in through `--mlflow` on training and inference/evaluation CLIs; default local tracking storage is `ai/mlflow.db` with artifacts in `ai/mlartifacts`, both ignored by git.
- Serving defaults to `ai/checkpoints/best-checkpoints.json`. Override binary checkpoint location with `--checkpoint` or `FH_MAHJONG_AI_CHECKPOINT`; large `.pt` files remain outside git except the deployed champion in `checkpoints/deploy/`.
- `fh-mj-serve-policy` is an inference boundary only. The Go server/bridge must still decode and validate returned `action_id` values against the current legal action set before applying them.
- Evaluation reports aggregate exact/top-3 agreement and action-family metrics for discard, chii, pon, kan, win, pass, haitei, and unknown action ids. Online evaluation also records reward distribution, round-outcome counts, and per-seat summaries for duplicate-seat comparisons.
- Heuristic trajectory samples preserve per-step rewards in `rewards` and attach round-outcome targets separately in `terminal_rewards` for warm-start consumers.
- IQL uses `steps_to_done` to discount sparse terminal round payout as `gamma ** steps_to_done * terminal_reward`, matching the Mortal-style sparse-reward target shape.
- IQL should not initialize `q_head` from BC policy logits by default; policy logits are action scores, not reward-scaled Q estimates. Use `--init-q-from-policy` only as an explicit ablation.
- `--cql-weight` adds a Mortal-style conservative Q penalty over legal masked actions; keep it as an explicit offline-RL ablation until duplicate-seat evaluation beats BC.
- The first implemented training loop is behavior cloning / offline warm-start. Conservative reward-based offline RL candidates are advantage-weighted BC and discrete IQL from a BC checkpoint; discrete IQL uses a separate Q head and defaults to discounted MC terminal-return targets so reward learning does not overwrite the inference policy head or depend on unstable sparse TD bootstrapping. Keep BC regularization enabled. Naive offline Q remains experimental until duplicate-seat evaluation beats the BC baseline.
