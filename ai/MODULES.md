### Contracts and configuration

- **pyproject.toml** — Package metadata, dependencies, and the 43 `fh-mj-*` console scripts.
- **config.py** — Dataclass configs for environment, model, training, advantage-weighted BC, discrete IQL, offline Q-learning, and self-play. `EnvConfig` defaults match the real Go bridge: `plane_shape=(39, 42, 1)`, `scalar_features=58`, `action_space_size=204`. `EnvConfig.match_mode` is `classic` or `chongci`; Chongci adds starting-score, bust-threshold, and max-hands fields passed through to protobuf.
- **model_config_args.py** — Shared CLI/model-config helpers for architecture ablations. `add_model_config_args` exposes `--model-event-hidden-dim`/`--model-event-output-dim` alongside `--model-event-window`; **`model_config_params()` enumerates all `ModelConfig` fields explicitly** (including `event_output_dim`/`growth_blocks`) for report/MLflow provenance, so **a new dataclass field must be added here by hand — it is not auto-derived from `dataclasses.fields`.**
  - **(gru-width)** `ModelConfig.event_output_dim: int = 0` (dormant default: `0` or `== event_hidden_dim` means "no projection module", state_dict byte-identical). When `> 0` and `!= event_hidden_dim`, `EventEncoder` appends an output projection — see model.py.
- **types.py** — Shared observation, transition, branch-evaluation, and bridge result types.
- **action_catalog.py** — Python labels and family helpers for the Go bridge's fixed 204-action catalog, using the same backend tile-face order as `internal/rl/action.go`.
- **events.py** — Python mirror of the packed public-event codec owned by `internal/rl/eventcodec.go` (Spec B1) — **change BOTH files or neither**; the golden vector in `tests/test_events.py` is shared byte-for-byte with the Go test. `decode_event`/`decode_history` unpack `Observation.event_history` (uint32 array, empty unless `EnvConfig.event_history_window > 0`; window 0 keeps observations byte-identical); `event_to_token` maps `(type, rel_seat, face)` to a [0, 2048) embedding index for B2's event encoder (flags/rel_from ride as separate features).

### Bridge and environment

- **bridge.py** — Abstract bridge contract, mock bridge, and `CtypesGoBridge` implementation for the Go RL library.
  - `MockMahjongBridge` retains the last emitted observation so `step()` validates actions against the real current legal-action mask instead of sampling a fresh one. It remains available for smoke tests, but `bridge_kind="go"` is the default for real work.
  - Bridges preserve `last_reset_result` so evaluation can count rounds that terminate during reset before the learning seat receives a decision.
  - `evaluate_branches()` asks the Go bridge to clone the current simulator state, apply candidate action ids, and finish each branch with deterministic heuristics; use this for exact same-state counterfactual label generation.
  - `CtypesGoBridge` decodes `round_outcome` / `terminal_outcome` protobuf messages into `StepResult.info` / `Transition.info`.
  - `CtypesGoBridge` owns the Go-side handle lifecycle and supports `close()`, context-manager usage, and best-effort cleanup in `__del__`.
  - `CtypesGoBridge.handle` / `.library` are public accessors (raw env handle, loaded `ctypes.CDLL`) for other ctypes wrappers — e.g. `GoSearchPool` — that need to attach FFI features to the same live env without reloading the library.
- **env.py** — Thin environment wrapper around the bridge.
- **envpool.py** — Env-pool abstraction for lockstep-round collection: `GoEnvPool` (batched FFI over `FHEnvPool*`, flat float32/uint8 observation buffers decoded with `np.frombuffer`) and `InProcessEnvPool` (loops ordinary bridges; test/CPU-exactness path). `make_selfplay_pool()` builds the all-4 self-play EnvConfig and picks the implementation by bridge kind. Pools never self-reset a slot — the caller owns the seed schedule. `PoolStepResult.event_histories` carries one TRUE-length uint32 array per observation row (decoded from the fixed-width count-prefixed flat buffers; validation raises on count/size mismatch); when the configured window is nonzero, `GoEnvPool` requires the response header window to match and raises `BridgeError` on a stale pre-B2a library.
- **searchpool.py** — `GoSearchPool`, the test-time search sibling of `GoEnvPool`: ctypes wrapper over `FHSearchPoolNew/Step/Close`, clones a live `CtypesGoBridge`'s current decision point into K determinized clones (`SearchPoolNewRequest{clones, seed, max_rollout_decisions, determinizations}`; `determinizations` is the common-random-numbers pairing group count K passed through to Go) and steps them with the same `EnvPoolStepRequest`/`EnvPoolStepResponse` wire format as `GoEnvPool` (identical decode path — `step()` delegates to `GoEnvPool._decode_response`, so event rows, buffer validation and the stale-bridge handshake are shared, then overlays `round_ended`). `.step()` returns `SearchStepResult` (`PoolStepResult` + `round_ended: dict[int, bool]`, true when a slot's `SlotState` carried a non-terminal `round_outcome` — the round ended mid-search and the observation is the next hand's first decision). Constructed from a live bridge (`GoSearchPool(bridge, clones, seed, max_rollout_decisions, determinizations=0, root_seat=None)`; `root_seat` populates the proto3-`optional` `SearchPoolNewRequest.root_seat` only when not `None`, pinning the search root explicitly for duplicate-seat eval) via `bridge.handle`/`bridge.library` public accessors on `CtypesGoBridge`, so the search pool binds onto the same loaded library instance and env handle instead of reloading the `.dylib`/`.so`.

### Model

- **model.py** — PyTorch policy/value/Q network for masked-action Mahjong decisions, defaulting to a Suphx-style no-pooling residual tile-plane encoder with an optional pooled ablation.
  - The Q path uses a Mortal-style dueling value/advantage head by default; channel attention is available as an explicit `ModelConfig(channel_attention=True)` ablation.
  - The shared trunk also exposes default-off state and action-conditioned large-loss probability/severity auxiliary heads for Chongci tail-risk experiments; serving still selects actions from the masked policy logits.
  - `infer_model_config(state_dict, metadata=None)` recovers a saved `PolicyValueNet`'s ModelConfig from tensor shapes, cross-checked against a throwaway `PolicyValueNet`'s state dict shapes/keys. **Spec B2c: metadata-authoritative for B2b architecture** (`event_window`/`privileged_critic`/`aux_heads`/`residual_blocks`, invisible to weight shapes alone): `metadata["model_config"]` (a full `ModelConfig`, saved by current training paths via `storage.model_config_metadata`) is authoritative when present; else `metadata["b2b"]` (the four-flag block older B2b checkpoints carry) overlays those four fields onto shape-inferred defaults; else, if the state dict carries no B2b modules at all, everything is shape-inferred (pre-B2b legacy path); else (B2b modules present, no usable metadata) this **raises** — a checkpoint's `event_window` genuinely cannot be recovered from shapes alone. `CheckpointPolicy.from_checkpoint` and `fh-mj-evaluate`'s checkpoint loading both go through this, so a checkpoint saved with `model_config` metadata never needs explicit `--model-*` override flags.
  - **(B2b)** `EventEncoder` (embedding+GRU over packed event uint32s, bit-decoded on device; gather-at-length, zero-length rows → zeros), privileged critic branch (`privileged_encoder` over `planes[:,39:51]` feeding ONLY the value head), aux heads (`belief_head`/`dealin_head`/`rank_head` reading the public trunk). ALL config-gated via `ModelConfig.event_window/privileged_critic/aux_heads` (default-off ⇒ state_dict byte-identical, champion loads strict). **The policy path always consumes `planes[:, :policy_channels]` (39) — the actor is information-legal by construction.**
  - **(gru-width)** When `ModelConfig.event_output_dim > 0` and `!= event_hidden_dim`, `EventEncoder.__init__(embed_dim, hidden_dim, output_dim)` appends `self.output_proj = nn.Linear(hidden_dim, output_dim)` and the forward pass projects the gathered GRU output through it. `EventEncoder.output_dim` (a property) reports the effective width either way, and every downstream consumer of the encoder's output width (trunk input columns, privileged value head, shape inference) reads that effective width instead of `event_hidden_dim` directly. New key namespace: `event_encoder.output_proj.{weight,bias}`.

### Training

- **ppo.py** — Online self-play PPO: `PPOConfig`, `RolloutBatch`, `masked_policy_distribution`, `masked_logprob(logits_row, temperature, action) -> float` (the one Torch log-prob computation both B2b collectors use for `old_logprobs`), `compute_gae`, `ppo_update` (masked clipped surrogate + value + entropy; telemetry — policy/value loss, entropy, `approx_kl`, `clip_fraction`, aux losses — is the row-weighted mean over ALL minibatches across all epochs, not the final minibatch's values, plus an `optimizer_steps` count; data-scale-960 Stage 0), `collect_rollouts` (on-policy; learning seat samples, frozen-anchor opponents, torch seeded per match for reproducibility), and `train_ppo` (warm-start anchor policy+value → collect → GAE → update → periodic duplicate-seat CI gate → checkpoint).
  - **This is the first ONLINE/on-policy trainer** — it can surpass the offline/heuristic ceiling because it learns from its own explored actions, unlike BC/IQL.
  - `PPOConfig.num_workers` enables parallel rollout collection; `1` keeps the sequential collector. `default_num_workers()` gives a core-aware default (rollout throughput is CPU-core-bound, ~380MB/worker so RAM is not the limit; scales near-linearly to ~8, knee near 16 on a 24-core box); it counts CPUs available to the process (`sched_getaffinity` + cgroup CPU-quota clamp), not the host total. The self-play/oracle CLIs default `--num-workers` to `min(default_num_workers(), --matches-per-iter)` so short runs don't spawn idle workers.
  - `train_ppo` trains against an opponent pool (anchor + past-learner snapshots) controlled by `--pool-max-size` / `--pool-snapshot-interval`; `pool_max_size=1` (default) is single-anchor-only. Opponents are sampled per match/seat deterministically from the pool; `pool_size` is logged to MLflow each iteration.
  - `PPOConfig.grp_checkpoint` / `--grp-checkpoint` replaces the per-hand score reward with a GRP (`GlobalEVNet`) placement-value delta: each non-terminal step receives `g_{t+1} - g_t` and the terminal step receives `realized_placement - g_last`, where `g` is the frozen GRP's predicted placement EV. The GRP is trained offline via `fh-mj-train-global-ev --reward-shaping placement` on anchor trajectories and stays frozen during PPO; the parallel collector ships the frozen GRP to workers so pool-composition changes take effect without reloading. `grp_checkpoint=None` (default) leaves the reward unchanged as per-hand score.
  - `PPOConfig.collect_dispatch_chunk` (0 = legacy single dispatch) bounds `ParallelB2bCollector` dispatch rounds — semantics-neutral like `num_workers` (per-match seeding; digest-proven), logged-not-rejected on resume, legacy config echoes back-filled.
  - **(B2b)** `RolloutBatch` optional `events/event_lengths/dealin_labels/rank_labels` (concat refuses mixed present/absent); `ppo_update` adds `AUX_LOSS_WEIGHT (0.1) * (belief_bce + dealin_bce + rank_ce)` with `-1`-masked rank rows; legacy metric schema untouched.
  - **(data-scale-960 Amendment 5)** `PPOConfig.minibatch_device_transfer` keeps the rollout host-resident and synchronously moves each minibatch to the update device — bit-identical update (same permutation RNG on the update device, global advantage normalization still computed there; pinned by `test_b2b_ppo`'s path-parity tests), required at 960 matches where the full-rollout transfer projects ~23.7GiB CUDA on a 24GB 4090.
  - **(mortal-scale-scratch)** `PPOConfig.head_lr` / `head_lr_iters` drive the two-group (`bc`/`heads`) lr schedule for `--scratch --init-from-bc` runs — see `train_b2b.py`'s `build_optimizer` (constructs the two AdamW groups) and `apply_lr_schedule` (sets each group's lr per iteration, idempotent across resume).
- **ach.py** — Clipped-NeuRD / ACH (Actor-Critic Hedge) policy update: `ach_policy_loss`, `ach_update`. Shares all of PPO's minibatch/epoch/grad-norm-clip/optimizer-step machinery — **the only difference is the policy loss**, which accumulates advantage the way CFR accumulates regret rather than PPO's clipped surrogate. Selected by `config.objective == "ach"` in `oracle.train_selfplay_oracle`, which dispatches `update_fn = ach_update if ... else ppo_update`.
- **oracle.py** — Oracle-guiding helpers: build a perfect-information policy warm-started from the 39-channel anchor and train it. Phase 1 `build_oracle_model` / `collect_oracle_rollouts` / `extract_deployable_student` / `train_oracle`; Phase 2 `collect_selfplay_rollouts` / `feature_dropout_schedule` / `train_selfplay_oracle` / `ParallelOracleCollector` / `ParallelSelfplayCollector`. The B2b surgery and training loop that used to live here ("by accretion", as this entry used to say) moved to `train_b2b.py` and `train_state.py`.
- **train_b2b.py** — B2b training: warm-start model surgery, rollout collection with hindsight labels, and the `train_b2b` PPO loop. Split out of `oracle.py`; the crash-resume machinery it drives is `train_state.py`, called as `train_state.X` so one monkeypatch target covers both callers.
  - **(B2b)** `build_b2b_model` (warm-start surgery: zero-init trunk event columns + privileged value columns ⇒ step-0 logits == champion, tested), `collect_b2b_rollouts` (51ch + events + hindsight labels via pure `_assemble_hindsight_labels`; bridge cfg carries the caller's chongci values — labels read from the SAME cfg; `action_selection="greedy"` is a test-only argmax mode), `ParallelB2bCollector`, `train_b2b`, CLI `fh-mj-train-b2b`. The per-match tail is shared with the batched collector: `_B2bMatchState` (per-seat row lists, `seat_hand_ids`, `hand_outcomes`, `match_net` from EVERY step's rewards incl. reset, `truncated`; `credit_step_rewards` / `record_outcome` helpers) is consumed by the pure `_finalize_b2b_match(ms, config, cfg, seed) -> (rows, telemetry)` (exact integer scores, placement bonus + its fail-closed raises, telemetry row, hindsight labels, seat-contiguous rows keyed by `_B2B_ROW_KEYS`); `_check_chongci_outcomes(chongci, completed, outcomes_seen)` is the stale-bridge guard every collector calls at the end. `ai/tests/test_b2b_collector_parity.py::test_process_collector_golden_digest` pins the process collector's output byte-for-byte — if it fails, the code is wrong, never the constants. Runbook: `worklog/plans/2026-07-16-spec-b2b-runbook.md`.
  - **(deep16-rezero)** `grow_b2b_model(anchor_checkpoint, growth_blocks, device="cpu")`: warm-starts a wider net by stacking `growth_blocks` `ReZeroResidualBlock`s (dormant at alpha=0) after a POST-B2b anchor's plane trunk — no tensor surgery, unlike `build_b2b_model`. The anchor must carry complete `metadata["model_config"]` (raises otherwise — `event_window` isn't shape-recoverable) and must itself have `growth_blocks == 0` (raises on an already-grown anchor — stacking two ReZero stacks is out of scope). Every non-`growth.*` anchor tensor must load same-shape (`load_compatible_checkpoint`'s skipped/missing keys, filtered to non-`growth.*`, must be empty or this raises) — step-0 parity (logits/value/Q/belief/dealin/rank all `torch.equal` vs the anchor) depends on zero silent drops. `train_b2b(..., growth_blocks=0)` routes construction through this when `growth_blocks > 0` (then `champion_checkpoint` must be a post-B2b anchor, not the raw 39ch champion the surgery path expects) and adopts the grown model's own `model_config` so checkpoint saves carry the true `growth_blocks`. CLI: `fh-mj-train-b2b --model-growth-blocks N` (default 0).
  - **(gru-width)** `widen_event_gru(anchor_checkpoint, new_hidden_dim, env_config=None, device="cpu")`: identity-masked GRU-widening warm-start (unlike `grow_b2b_model`'s block-stacking, this widens an EXISTING recurrent layer in place). Anchor must carry complete `metadata["model_config"]` with `event_window > 0` and `event_output_dim == 0` (both the metadata claim AND the absence of `event_encoder.output_proj.weight` in the state dict — an anchor whose metadata lies about being unwidened is rejected before surgery); `new_hidden_dim` must exceed the anchor's `event_hidden_dim`. Surgery (PyTorch GRU gate order r,z,n; per-gate row blocks): old-unit rows of `weight_ih_l0`/biases copied; `weight_hh_l0`'s `[old-gate-rows, old-cols]` block copied but the `[old-gate-rows, new-cols]` block explicitly **ZEROED** (old units must never see new-unit activations); new-unit rows/cols keep normal init (masked out by the projection, so their values don't affect step-0 outputs); the new `output_proj` is `[I_{H_old} | 0]` with zero bias. Every non-surgical tensor must load same-shape (fail-closed on any other skipped/missing key). `train_b2b(..., widen_event_hidden=0)` routes through this when `> 0` (mutually exclusive with `growth_blocks > 0` — CLI rejects both set) and adopts the widened model's own config for checkpoint metadata. CLI: `fh-mj-train-b2b --widen-event-hidden N` (default 0). Runbook: `worklog/plans/2026-08-02-gru-width-runbook.md`.
  - **(mortal-scale-scratch)** `build_scratch_model(env_config, model_config, device="cpu", bc_checkpoint=None)`: no anchor, no surgery — a freshly initialised B2b net (default PyTorch init throughout). With `bc_checkpoint` (`--init-from-bc`), the BC-stage weights under exactly `SCRATCH_BC_PREFIXES` (`plane_stem.`, `plane_blocks.`, `plane_head.`, `scalar_encoder.`, `trunk.`, `policy_head.`) are copied by name+shape — any missing/extra/shape-mismatched key on those prefixes is a hard error: a BC stage trained with a different `--model-*` set would otherwise silently partial-load. The two commands name three of those flags differently — `fh-mj-train-bc`'s `--model-event-window` / `--model-privileged-critic` / `--model-aux-heads` correspond to `fh-mj-train-b2b`'s `--event-window` / `--privileged-critic` / `--aux-heads`, and `fh-mj-train-b2b` IGNORES the `--model-*` forms of those three; every other shared `--model-*` flag keeps the same name on both. `trunk.0`'s trailing event-input columns (sized off `model.event_encoder.output_dim`) are then explicitly zeroed, because BC always trains with `events=None` (zero event vector), so those columns come out of BC as untouched random init; copying them onto the scratch model's own freshly-initialised event encoder would inject noise into step-0 logits. Zeroing them makes step-0 PPO logits exactly equal the BC policy — the untrained GRU contributes nothing until PPO moves it. Rejects `model_config.growth_blocks > 0` outright (`growth.*` tensors sit outside `SCRATCH_BC_PREFIXES`, so a BC load would leave them silently random). `train_b2b(..., scratch=True, init_from_bc=None|Path)` routes through this and persists `metadata["init"] = {"kind": "scratch"|"champion", "bc_checkpoint_sha256": ..., "bc_checkpoint_path": ...}` in `train_state.pt`, carried across resume. The BC file is read exactly once inside `build_scratch_model` (weights and digest from the same bytes); the digest rides back on the returned model as `init_from_bc_sha256`. CLI: `fh-mj-train-b2b --scratch [--init-from-bc PATH]`.
  - **(mortal-scale-scratch)** `verify_bc_transfer(model, bc_checkpoint, env_config, probe_seed=20260825, probe_batch=64)`: Amendment 1 §4's step-zero gate, run automatically by `train_b2b` for every `--init-from-bc` construction and fail-closed *before* any artifact is moved or any rollout collected. It re-reads the BC file exactly once and requires the digest to equal the `init_from_bc_sha256` `build_scratch_model` stamped on the model (an atomic replacement between the two reads would otherwise prove parity against bytes the run never loaded), rebuilds the BC net on the model's own device, and asserts EXACT equality — no tolerance, since both sides feed an exactly-zero event term through identical weights — of legal-action logits, full-row probabilities and greedy actions on a seeded synthetic probe (BC forwarded with `events=None`, scratch with random events), plus byte-equality of every loaded tensor with `trunk.0.weight` split into leading columns (equal to BC) and trailing event columns (exactly zero). The claim is scoped to the policy path; values and aux heads have no BC counterpart. The returned record — `probe_seed`, `probe_batch`, `bc_checkpoint_sha256`, `max_abs_logit_diff`, `max_abs_prob_diff`, `greedy_match_rate`, `loaded_keys`, `unloaded_keys`, `loaded_tensors_identical` — is persisted as `metadata["init"]["transfer_gate"]` and carried across resume; champion and legacy inits store `None` there (nothing to be equal to, not a gate that passed).
  - **(mortal-scale-scratch)** `split_bc_parameter_groups(model)` / `build_optimizer(model, config)` / `apply_lr_schedule(optimizer, config, iteration)`: Amendment 1 §6's two-rate schedule. `split_bc_parameter_groups` partitions parameters purely by name against `SCRATCH_BC_PREFIXES`, so a resumed run rebuilds identical groups and `optimizer.load_state_dict` matches. `build_optimizer` returns a single-group AdamW when `config.head_lr is None` and otherwise two groups NAMED `"bc"` (BC-loaded parameters at `config.lr`) and `"heads"` (event encoder, value/Q, privileged critic, aux and risk heads at `config.head_lr`). `apply_lr_schedule` is called every iteration before the update — idempotent, so the first iteration after a resume lands on that iteration's rates rather than inheriting the restored optimizer's — and decides what to schedule from the OPTIMIZER's own group names, not from the config, so a config/optimizer disagreement can never leave the heads group running at a head rate while the telemetry reports `lr`. It returns `{"lr_bc", "lr_heads"}`, which `train_b2b` merges into each iteration's `history.json` row. `PPOConfig.head_lr`/`head_lr_iters` (both whitelisted in `train_state._LEGACY_ECHO_ADDITIONS`, so pre-existing `train_state.pt` files still resume) require `--scratch --init-from-bc` and require each other: `head_lr` without `head_lr_iters >= 1` schedules a zero-length warm phase and `head_lr_iters` without `head_lr` builds no second group, so both raise instead of training silently single-rate. CLI: `fh-mj-train-b2b --head-lr 2e-4 --head-lr-iters 25`.
- **train_state.py** — Crash-resume machinery for `train_b2b`: the atomic `train_state.pt` writer and its previous-generation fallback, resume config-echo validation, history reconciliation, run-id lineage checks, stale-checkpoint quarantine, the checkpoint-directory lock, and bridge-library pinning. `train_b2b.py` is the only caller.
  - **`train_b2b` resumable state (deep16-rezero)** — `train_b2b(..., train_state_every=5, resume_from_state=None)`: every `train_state_every` iterations (and always at completion) atomically writes `<checkpoint_dir>/train_state.pt` (model + optimizer + torch/cuda/numpy/python RNG state + `next_iteration` + a `config_echo` of the env/model/PPO configs), so a multi-day lap survives a box restart. `resume_from_state=PATH` skips the champion/growth warm-start entirely — the model is built from the CALLER-supplied `model_config` (which must already be the run's effective architecture, e.g. the anchor's config with `growth_blocks` folded in) and loaded from the state file; the caller's env/model/PPO config and `base_seed` are validated against the state file first (any drift raises `ValueError` naming both saved and requested values), then training continues from `next_iteration`, reconciling `history.json` (dropping/re-appending rows at or after the resumed iteration so a state file slightly stale relative to `history.json` never duplicates rows). `history.json` is atomically replaced after every completed iteration; a missing or malformed history file resets only the JSON log rows with a warning while resume continues from the unaffected atomic state and per-iteration checkpoints. Every run (fresh or resumed) carries a `run_id` (uuid4 hex, generated at fresh-run start), persisted in both `train_state.pt["run_id"]` and `history.json`'s `{"run_id": ..., "rows": [...]}` wrapper; `--resume-from-state` requires `state.run_id == history.run_id` and raises naming both on mismatch, so a state file can never be resumed against an unrelated run's history/checkpoints in the same directory (legacy bare-list `history.json` files, which predate `run_id`, are accepted only when the state file also predates `run_id`). Use `train_state.read_b2b_history_rows(path)` to read history rows regardless of format. A `next_iteration` already `> config.iterations` raises `ValueError` (nothing to resume) instead of silently exiting with an unchanged history. CLI: `fh-mj-train-b2b --train-state-every N --resume-from-state PATH` (`--champion` becomes optional — and is ignored — once `--resume-from-state` is given; `--train-state-every 0` disables state-file writes). Runbook: `worklog/plans/2026-07-24-deep16-rezero-runbook.md`.
- **offline_trainers.py** — Self-play collection, behavior-cloning, advantage-weighted BC, discrete IQL, and conservative offline Q-learning trainer utilities.
  - Discrete IQL can optionally use a frozen external action-risk checkpoint as a training-side policy regularizer, penalizing policy probability on legal actions above a risk threshold, optionally scoped to one action family such as `discard`.
  - Discrete IQL also supports `large_loss_bc_weight`, an explicit tail-preserving behavior-cloning constraint applied only to transitions whose terminal return is at or below `large_loss_threshold`.
- **batched_selfplay.py** — Batched self-play collector: one pool call + ONE batched model forward per round (GPU-friendly), per-match numpy RNG sampling (`sample_masked_action`; no global torch RNG), δ feature-dropout with the same per-match mask stream as the process collector, per-seat-contiguous emission flushed in SEED ORDER (makes per-row-CPU output invariant to slot count — tested as full-array equality). `PPOConfig.collector="batched"` + `pool_slots` select it in `train_selfplay_oracle`; `"process"` remains the default until the throughput/quality gate passes.
- **parallel_rollouts.py** — `ParallelRolloutCollector` parallelizes full-match self-play rollouts across a persistent spawn-context pool of CPU-inference workers, concatenates their batches, and leaves the PPO update in the main process. It deterministically matches the sequential collector over the same seeds. The collector ships the full opponent pool to workers each iteration so pool composition changes take effect immediately.
- **selfplay_loop.py** — Chongci self-play improvement loop: pure two-stage CI promotion gate (`screen_pass` / `confirm_promote` / `gate_decision`), resumable JSON `LoopLedger`, `LoopConfig`, and `run_iteration` / `run_loop` that orchestrate generation → fresh-IQL training (from a fixed init on accumulated data, never fine-tuning the rolling best) → duplicate-seat gate. **Monotonic by design: the current best only changes on a CI-confirmed gain.**

### Data and storage

- **data.py** — Episode grouping (`split_episodes`), episode-safe train/validation splitting, terminal-reward backfill (`backfill_returns`), `steps_to_done` utilities, and `placement_shaped_returns()` which converts the per-seat terminal-reward vector into rank-based placement values (ranks 1-4 map to a configurable table, ties averaged) for placement-aware reward shaping.
- **buffer.py** — Object and array-backed replay buffers with terminal-reward-aware value targets plus next-observation/reward/done fields for TD learning. Both accept `reward_shaping="placement"` (plus `placement_values`) to return rank-based placement returns instead of raw per-seat net score. `ArrayReplayBuffer` can also sample from BC-only arrays that omit next-state TD fields.
- **streaming_buffer.py** — Memory-bounded streaming replay for IQL: `build_shard_index`, a PyTorch `TransitionIterableDataset` (per-epoch shard shuffle + bounded shuffle buffer, multi-worker shard partitioning), `collate_transitions`, and `StreamingReplayBuffer` (same `.sample`/`__len__` as `ArrayReplayBuffer`, backed by a `DataLoader`). Lets `fh-mj-train-iql --stream` / `fh-mj-selfplay-loop --stream-training` train on datasets larger than RAM; one epoch sees every row once. Reuses `buffer.train_batch_from_arrays` so streamed and in-memory batches are identical. **Does not support the pairwise/risk-trace auxiliary paths (raises if combined).**
- **storage.py** — Checkpoint, JSONL, and sharded NumPy transition persistence helpers.
  - `read_transitions()` accepts either JSONL or a NumPy shard directory containing `manifest.json`; `read_transition_arrays(..., keys=...)` can load only the arrays a trainer needs.
  - `ShardedTransitionWriter` supports incremental direct-to-shard generation without a temporary JSONL file.
  - Sharded transition data preserves `steps_to_done` and compact terminal outcome fields for offline diagnostics. Mixed self-play shards additionally preserve numeric `policy_source_ids` and optional `policy_values`; the dataset manifest maps source ids to checkpoint/random/heuristic seat policies.
- **checkpoint_manifest.py** — Loader/resolver for tracked best-checkpoint metadata in `ai/checkpoints/best-checkpoints.json`; binary checkpoint files stay outside git except those under `checkpoints/deploy/`. Serving resolves the classic current checkpoint with `current` and the Chongci current checkpoint with `current_chongci`.

### Policies, search, and serving

- **policies.py** — Random, torch-backed, and Q-margin guarded policy adapters; guarded evaluation chooses anchor/candidate actions from policy logits and uses the candidate Q head only as a confidence margin.
  - `TailConstrainedCandidatePolicy` lets a reward-trained candidate override the anchor only when candidate Q improves and an action-risk model predicts no large-loss probability increase over the anchor action, with optional tolerance and absolute risk ceiling.
  - `RiskGuardedPolicy` keeps the anchor action by default and only switches to a lower-risk legal action when an action-risk critic predicts the anchor action is risky and the substitute is close enough under anchor policy logits. Use `selection_mode="policy_nearest"` when auditing whether policy-preserving substitutes beat the legacy lowest-risk substitute ranking.
- **search.py** — `SearchPolicy`, an `ActionChoice`-protocol policy doing determinized champion-rollout test-time search. `SearchConfig(num_determinizations=16, max_candidates=4, prior_mass_cutoff=0.95, max_rollout_decisions=512, seed=1, discount_gamma=0.99)`. `choose()`: take the root prior's top actions (capped by `max_candidates`/`prior_mass_cutoff`); if ≤1 candidate return the plain greedy action (pool never built). Otherwise build `len(candidates)*K` clones via an injected `pool_factory(num_clones, seed, max_rollout_decisions, determinizations=K, root_seat=observation.seat)` (K passed as a keyword so the Go pool pairs worlds by determinization; `root_seat` passed EXPLICITLY so the Go pool roots on the seat actually being searched — under duplicate-seat eval `currentActionSeat()` may surface a lower-numbered heuristic opponent instead; production wires `GoSearchPool`, tests inject fakes), score them, return the best candidate's action.
  - Algorithm: clone `c*K+k` gets candidate `c` on the FIRST `pool.step` (whose response already carries rewards and may terminate/round-end/truncate/error a clone — absorbed immediately); thereafter batch ALL live clones' obs rows through one `checkpoint_policy.evaluate_batch` per round and each clone plays masked greedy argmax. Per clone accumulate `step_rewards[root_seat]` from every step, **DISCOUNTED by the ROOT-seat decision horizon t** to match the champion value head's training convention (`compute_gae`, gamma=0.99, over per-seat-contiguous trajectories): the apply is root-decision 0, a reward absorbed at horizon t carries `gamma^t`, t increments when the clone's next ROOT-seat decision is issued (its obs row `SlotMeta.seat == root_seat`) so rewards between root decisions k and k+1 carry `gamma^k`; `round_ended`/`truncated` → add `gamma^(t+1)` × the value head of the returned obs row (one root-step ahead, batched bootstrap call) and mark done; `terminated` → accumulated discounted reward is final (no bootstrap). `discount_gamma=1.0` recovers the old undiscounted sum. Candidate score = mean over its surviving clones.
  - The rollout loop's own Python-side iteration bound (`2*max_rollout_decisions + 32`) is a defensive backstop only — Go defers ITS cap to the root seat's next decision, so this loop is intentionally slack and Go's truncated/round_ended rows are the normal cutoff signal. If the Python bound ever fires with a clone still live, `_bootstrap_live` value-bootstraps it ONLY when its current obs row's `SlotMeta.seat == root_seat`; a foreign-seat row at that point means the clone never reached a scoreable root-seat state, so it is EXCLUDED from its candidate's mean via the same `errored`-drop mechanism as a real per-clone error (never value-bootstrapped — that would feed the value head an out-of-distribution input).
  - **Fail-open**: any exception in the search path (incl. the pool factory) → greedy action + `fallback_count` increment; a candidate whose every clone errors (including this foreign-at-cutoff exclusion) scores `-inf` unless it is the greedy action (kept at the root value estimate) and counts a fallback.
- **serving.py** — Checkpoint-backed inference helpers and bridge smoke tests for serving actions while the Go bridge validates legality. `CheckpointPolicy.from_checkpoint` infers the network architecture from the checkpoint via `infer_model_config`, so promoted checkpoints may differ in depth/width from `ModelConfig` defaults.
  - `CheckpointPolicy.from_checkpoint(..., sample_temperature=T, sample_top_k=K, sample_action_family=F, seed=S)` can sample legal masked actions for dataset generation; keep the default `T=0.0` / `K=0` for greedy serving/evaluation. Family-scoped sampling only applies when every legal action belongs to that family, e.g. discard-only exploration rows. Served actions expose `greedy_action_id`, `sampling_applied`, and `sampled_from_greedy` so mixed self-play can distinguish true exploration from sampled calls that matched the greedy anchor.
  - `CheckpointPolicy.evaluate_batch(planes, scalars, action_masks, chunk_size=256, events=None, event_lengths=None) -> (probs [N,204] float32, values [N] float32)` is the batch/deterministic sibling of `choose()` for the post-game review pipeline: no sampling, `torch.inference_mode`, softmax over legal actions only with exact zeros on illegal ones (mask applied both to model logits and post-softmax), and the same scalar zero-padding as `choose()`. Chunking is purely a memory knob — output is chunk-size-invariant. `events`/`event_lengths` (Spec B2c) are optional int64/int32 tensors shaped like `TorchGreedyPolicy`'s per-row event rows (`[n, model_config.event_window]` / `[n]`); unlike `choose()`, this batch entry point has no per-row `Observation` to validate against, so it does NOT raise on a missing/empty history — callers batching event-model observations (`serve_policy.py`'s `/evaluate`) are responsible for supplying real histories.
  - `CheckpointPolicy.choose(observation)` threads events into every forward exactly like `TorchGreedyPolicy` (tail-window + explicit length), but for an event model (`model.wants_events`, i.e. `event_window > 0`) it **RAISES on an EMPTY `observation.event_history`** instead of silently zero-filling — defense-in-depth behind `serve_policy.py`'s own `observation_from_json` validation, since serving an event model on a silently-zeroed history would answer a decision the model was never trained to make. A genuinely early-round history is short, never empty (every bridge emits at least one event before the first decision reaches serving).

### Evaluation and diagnostics

- **evaluate.py** — Offline action-agreement scoring with action-family breakdowns, duplicate-seat evaluation, and online live-play evaluation against the heuristic baseline. Both agreement helpers (`compute_action_agreement`, `compute_action_agreement_from_batches`) report `mean_cross_entropy` — the legal-action-masked negative log-likelihood of the taken action — next to `agreement_rate`; it is the quantity `fh-mj-train-bc --patience` selects and stops on. `reward_summary()` reports `sem` and `ci95`; online and duplicate-seat reports expose `mean_reward_sem`/`mean_reward_ci95` so checkpoint comparisons can use CI-separated promotion gates.
  - Online reports include precise mean/sum reward, reward distribution, action-family rates, and duplicate-seat `seat_summary`. Online evaluation sums per-step rewards per episode through `episode_reward_vector`, so Chongci dense step rewards recover the final match outcome.
  - `evaluate_policy_online(policy=None, policy_factory=...)`: when `policy` is `None`, `policy_factory(bridge)` is called right after the bridge is built (a policy needing the live bridge — e.g. a search policy's rollout pool — can't be constructed before the bridge exists). `evaluate_duplicate_seats_policy`'s per-seat `policy_factory(seat)` is threaded through this lazily via `_invoke_seat_policy_factory`, which inspects the factory's arity: a 1-arg factory (the sampling/guarded precedent) is still called as `factory(seat)`, just after the bridge exists instead of before (no observable difference); a 2-arg factory is called as `factory(seat, bridge)`, giving it that seat's own live bridge (used by `--search`'s `search_policy_factory`).
  - Online/duplicate evaluation accepts `match_mode="chongci"` plus Chongci score/hand-cap config; Chongci reports `positive_reward_rate` as the final-match net-positive metric while keeping `win_rate` as a backward-compatible reward-positive alias. It also supports non-model policy adapters such as Q-margin and risk guards while preserving the same duplicate-seat metrics; guarded-policy reports include generic intervention summaries by source and action family.
  - Duplicate-seat evaluation reports `mean_placement` (mean rank among the four seats, 1 = best) alongside `mean_reward` (net score); **use `mean_placement` as the primary objective when evaluating GRP-shaped PPO checkpoints** and compute an anchor baseline placement too.
  - **Clustered CIs (2026-07-14)** — duplicate-seat reports add `per_seed_mean_placements`, `mean_placement_ci95_clustered` (t-interval over per-seed 4-rotation means), and `cluster_design_effect` (clustered/naive variance ratio) alongside the existing naive iid fields. The four seat-rotations of one wall seed are correlated, so **the naive `mean_placement_ci95` understates the true interval; use the clustered fields for any promotion or lever verdict.** Compare two reports with `fh-mj-compare`, never by diffing means by hand.
- **hand_stats.py** — Per-hand Tenhou/Majsoul-style outcome statistics for heuristic benchmarking (`summarize_hand_stats`, `bootstrap_hand_stats_ci`). Inputs are actual per-seat nets, so Fenghua liability rules are already reflected. Consumed by `evaluate.py` and `scripts/benchmark.py`.
- **reward_calibration.py** — Offline Q/value calibration diagnostics against discounted terminal round payout targets, with action-family and target-sign breakdowns. When `--large-loss-threshold` is supplied it also reports large-loss probability/severity calibration for target-side risk experiments, defaulting to action-conditioned risk heads when available, with per-action-family diagnostics so tail-risk failures can be separated by family.
- **global_ev.py** — Visible-state global expected-value predictor for Chongci-style match outcomes. Trains a separate value model from observation tensors to final acting-seat terminal reward and reports against a constant train-mean baseline before the signal is used for policy work. `global_ev_targets()` accepts `reward_shaping="placement"`; IQL `--target-mode global_ev_td` then bootstraps placement-aware Q targets. `ActionGlobalEVNet` supports `EV(state, action_id)`.
- **global_ev_diagnostics.py** — First-divergence diagnostics that score paired trace anchor/candidate observations with a frozen global EV model and report predicted-vs-actual reward deltas by action-family pair. Also includes exact branch-CF calibration helpers for action EV (preferred-action rate, reward-gap-weighted preferred rate, guard-preflight margins).
- **paired_trace.py** — Paired online trace diagnostics for comparing two checkpoints on the same seed/seat schedule and recording first action-divergence contexts.
  - Observation summaries name Chongci score-pressure scalars for risk reports: leader pressure, large-loss safety margin, own bust safety, and opponent large-loss pressure.
  - Summaries include `counterfactual_supervision`, converting first-divergence outcome differences into preferred/avoided action-family counts and tagging new deal-in / new large-loss cases before training on paired labels.
  - Comparison can resume from existing seed/seat pairs and skip completed entries, so long tensor-bearing trace jobs can be checkpointed instead of writing only at the end.
  - `--max-divergences` can persist additional aligned action disagreements after the first divergence. **Treat those later rows as risk-calibration evidence only**; after the first different action, paired trajectories are no longer guaranteed same-state counterfactuals.
  - Reports include compact visible `pre_divergence_sequence` rows for sequence-aware paired-delta diagnostics. These rows must remain reward-free and hidden-info-free.
- **paired_trace_delta.py** — Direct paired-trace candidate-anchor reward-delta model and diagnostics. Use it after action-EV regressors overfit source windows: it predicts the final reward delta from the shared first-divergence visible scalars/context plus both divergent action ids, instead of assigning absolute EV to each action separately. The optional sequence model consumes compact visible pre-divergence prefix rows. **Keep this diagnostic-only until it passes independent holdout preflight**; do not use it for guarded serving from train-window gains alone.
- **paired_trace_q_diagnostics.py** — Q/policy ranking diagnostics for tensor-bearing paired traces. Use it after a live smoke/gate reject to check whether a checkpoint's Q head ranks realized preferred first-divergence actions above avoided actions before allowing another policy-improvement update.
- **paired_trace_action_ev.py** — Conversion helpers behind `fh-mj-build-paired-trace-action-ev-data`: turn paired-trace first-divergence outcome deltas into the branch-action EV NPZ schema.
- **branch_counterfactuals.py** — Exact Go-branch counterfactual helpers that select best/worst branch outcomes from `evaluate_branches()` and build pairwise NPZ arrays for IQL auxiliary training. Broad branch-CF generation defaults to discard-only labels; sampled-vs-greedy generation can pass all action families and records greedy/sample action ids for diagnostics.
- **branch_cf_calibration.py** — Diagnostics for exact branch-counterfactual shards: whether policy logits, Q values, and optional action-risk heads rank the preferred branch action above the avoided action before using branch labels for more training. Also provides failure-slice summaries for Q/policy misranked rows, including action-pair counts, high-gap examples, and visible scalar summaries.
- **near_state_counterfactuals.py** — Filters tensor-bearing paired traces into stricter discard-vs-discard near-state cases. Requires both chosen discard actions to be legal in both recorded observations plus bounded visible-scalar and action-mask distance; **use it for risk data mining, not direct checkpoint promotion.**
- **risk_filter.py** — Utilities for extracting high-risk first-divergence cases from paired trace reports and applying per-transition sample weights plus optional pairwise preferred/avoided action labels and reward-delta targets. **The loader must use each report's stored `left_label` / `right_label`** when resolving reward and outcome keys, because Chongci diagnostics often use named candidates such as `candidate_t054_w075` rather than the generic `candidate`.

### Scripts — data generation

- **scripts/generate_data.py** (`fh-mj-generate-data`) — Heuristic trajectories → JSONL or sharded NumPy plus dataset manifest via the Go bridge (or mock fallback). `--match-mode chongci` forwards Chongci config for multi-hand generation. `--chunk-size` bounds each bridge export request and preserves globally unique `episode_index` values across chunks. `--format npz-shards` writes chunks directly to sharded storage. Long jobs print per-chunk progress and record elapsed seconds in the manifest. `--learning-seat-rule seed-mod-4` (`--seat-rule-base-seed`, default `--start-seed`) keeps only seat `(episode_seed − base) % 4` per episode, filtering each chunk before serialization and recording `learning_seat_rule`, `seat_rule_base_seed`, `per_seat_transitions` and per-chunk `transitions_before_seat_filter` in the manifest; default `all` keeps every seat.
- **scripts/generate_selfplay.py** (`fh-mj-generate-selfplay`) — Mortal-style mixed self-play where selected seats are controlled by checkpoint/random Python policies and the Go bridge auto-plays heuristic seats.
  - `--seat-policy` supports `seat=checkpoint:/path/to.pt`, `seat=random`, and `seat=heuristic`; omitted seats default to heuristic. Checkpoint seat policies may append per-seat sampling overrides such as `3=checkpoint:/path/epoch_001.pt?temperature=0.75&top_k=3&sample_family=discard`, allowing greedy anchor seats and one controlled exploration seat at the same table.
  - `--checkpoint-temperature T` samples checkpoint logits for exploration data while preserving deterministic seeding and recording the temperature in the manifest (default `0.0` = greedy); `--checkpoint-top-k K` restricts sampling to the top-K legal actions; `--checkpoint-sample-action-family F` limits sampling to decisions where all legal actions are in family `F` (per-seat `sample_family` overrides it).
  - Output uses the same JSONL or sharded NumPy format as heuristic generation, with per-transition policy source ids.
- **scripts/convert_data.py** (`fh-mj-convert-data`) — Convert JSONL transition data into sharded NumPy replay storage.
- **scripts/generate_branch_counterfactuals.py** (`fh-mj-generate-branch-counterfactuals`) — Collect states from checkpoint/random self-play seats, evaluate legal discard branches from the exact cloned Go state, and write direct pairwise NPZ shards for `fh-mj-train-iql --pairwise-data`. Use after paired-trace coverage is too sparse: it labels alternate legal discards from one state directly instead of waiting for two policies to diverge. The default branch mode stops at the next round end, the practical label for Chongci; use `--branch-through-match-end` only for expensive full-match ablations, and include `--progress-every N` plus `--max-elapsed-seconds S` on remote probes.
- **scripts/generate_sampled_branch_counterfactuals.py** (`fh-mj-generate-sampled-branch-counterfactuals`) — Run a checkpoint with seeded top-k sampling, branch-evaluate greedy-anchor vs sampled action whenever they differ, and write exact same-state pairwise shards. Use after top-k sampled self-play improves exploration diversity but broad IQL on the sampled data fails. For Chongci probes keep `--max-steps-per-episode 0` unless deliberately testing truncation, so the bridge uses its match-mode default and avoids false zero-reward `match_truncated` smoke reports.
- **scripts/generate_targeted_branch_counterfactuals.py** (`fh-mj-generate-targeted-branch-counterfactuals`) — Replay an anchor checkpoint to seed/seat/decision targets from paired-trace or action-EV reports, evaluate exact legal branches at those live Go states, and write pairwise NPZ shards. Use after guard preflight false positives identify high-impact contexts broad branch-CF data misses. **Replay one learning seat at a time** so the Go state matches the original paired trace.
- **scripts/build_paired_trace_action_ev_data.py** (`fh-mj-build-paired-trace-action-ev-data`) — Convert tensor-bearing paired trace first-divergence outcome deltas into the branch-action EV NPZ schema (`branch_preferred_rewards` / `branch_avoided_rewards`). Use when same-state branch-CF labels rank local alternatives but fail full paired-trace preflight; it trains from actual anchor-vs-candidate match reward differences instead of only best/worst branch rollouts. Keep `--divergence-source first` for strict evidence; later/all rows are aligned by trace index only. `--include-trajectory-context` appends `pre_divergence_context` scalars and requires downstream scripts that preserve the wider scalar shape.
- **scripts/build_counterfactual_risk_data.py** (no console entry) — Convert tensor-bearing paired trace first-divergence labels into a tiny sharded NPZ dataset with direct preferred/avoided action-risk supervision. Like `risk_filter.py`, **must honor each report's stored `left_label` / `right_label`** instead of assuming generic `anchor`/`candidate` keys. `--preferred-policy <label>` builds anchor-preserving shards (e.g. `promoted_anchor`, keeping only rows where the anchor beat a rejected candidate); `--preferred-action-family`/`--avoided-action-family` build narrow failure-slice shards; `--training-target-policy preferred` is for teacher-policy distillation only (default `avoided` preserves risk/negative-example behavior); `--divergence-source later|all` is for broader aligned-disagreement calibration only (default `first` is the strict same-state path).

### Scripts — training

- **scripts/train_bc.py** (`fh-mj-train-bc`) — Behavior cloning with deterministic episode-level train/validation split, validation agreement reporting, checkpointing, and resume. Takes the shared `--model-*` flags (`add_model_config_args`), so the BC stage can build the exact trunk a later `fh-mj-train-b2b --init-from-bc` run will load, and records that `ModelConfig` in every checkpoint's metadata. Writes a JSON report with train/validation transition counts, per-epoch losses, validation exact agreement, top-3 agreement, action-family agreement, and `mean_cross_entropy`. `--patience N` stops after N consecutive epochs without a `--min-delta` (default `1e-4`) absolute improvement in validation cross-entropy, never before `--min-epochs`, and requires a validation split (it raises without one); the report then carries `stopped_early`, `epochs_run`, `best_epoch` and `best_validation_cross_entropy`, and the lowest-CE epoch's checkpoint is byte-copied to `<checkpoint-dir>/best.pt` — the file the scratch lap initializes from. Runbook: `worklog/plans/20260825-mortal-scale-scratch-runbook.md`.
- **scripts/train_awbc.py** (`fh-mj-train-awbc`) — Advantage-weighted behavior cloning, the first conservative offline RL improvement over a BC warm-start.
- **scripts/train_iql.py** (`fh-mj-train-iql`) — Discrete implicit Q-learning with MC terminal-return targets by default, optional TD Q targets, expectile value learning, advantage-weighted policy updates, optional CQL penalty, BC regularization, pairwise divergence preference loss, and optional transition limiting for memory control.
  - **Targets and shaping**: `--target-mode global_ev_td --global-ev-checkpoint PATH` uses a frozen visible-state global EV model for Bellman targets (immediate reward plus discounted next-state global EV) — the Mortal/Suphx-style bridge between a calibrated outcome predictor and policy/Q learning. `--reward-shaping placement` (plus optional `--placement-values`) replaces the raw net-score MC return target with rank-based placement value; combine with a placement-trained GlobalEV under `--target-mode global_ev_td`. Treat it as an isolated reward-target ablation: train on the same data as the raw baseline and promote only on the duplicate-seat CI gate.
  - **Head freezing**: `--critic-only` freezes the policy-selection path and trains only `q_head.*`/`value_head.*` — use for Q-ranking diagnostics before letting a failed reward-learning branch influence policy logits. `--policy-head-only` freezes encoder and critics and trains only `policy_head.*` — use only for constrained exact-branch policy fixes that have passed Q-ranking preflight.
  - **Multi-dataset**: repeat `--data` to train from multiple datasets (e.g. existing heuristic shards plus new mixed self-play shards); the trainer samples across them through a composite replay buffer without rewriting the sources.
  - **Tail/risk weighting**: `--large-loss-threshold` plus `--large-loss-penalty` gives default-off large-loss utility shaping — use it only as an explicit Chongci reward-learning ablation, and keep promotion decisions on duplicate-seat EV/positive-rate/large-loss gates, never training loss. `--large-loss-weight` upweights transitions at or below `--large-loss-threshold` (reweighting Q/value/policy/BC/CQL losses without changing the sampled dataset or the deployed policy rule); `--large-loss-bc-weight` adds a policy-only preservation term on those rows (use when a candidate improves EV but regresses large-loss rate); `--large-loss-aux-weight`/`--large-loss-severity-weight` train target-side tail-risk heads from terminal returns without changing deployed action selection, and `--large-loss-aux-detach` trains them from detached trunk features for diagnostic ablations.
  - **Risk-trace supervision**: `--risk-trace-report` upweights transitions matching paired-trace first-divergence risk cases when dataset start seeds are supplied through `--risk-trace-dataset-start-seed`. `--risk-trace-filter-datasets` keeps the first `--data` input as the normal anchor/base replay source, then filters later risk-trace datasets down to exact matched first-divergence rows plus `--risk-trace-context-radius` same-episode/same-seat context. `--risk-trace-counterfactual-labels` broadens supervision to all first-divergence labels above `--risk-trace-min-counterfactual-reward-gap`, still requiring exact seed/seat/decision/action replay matches.
  - **Pairwise preference**: `--pairwise-weight` adds a policy-logit margin loss preferring the anchor action over the candidate on matched high-risk rows; `--pairwise-q-weight` applies the same to the Q head; `--pairwise-replay-multiplier` repeats those sparse rows into an auxiliary replay source (and also repeats rows loaded through direct `--pairwise-data`, required when exact branch-CF shards are much smaller than the main replay). `--pairwise-data` adds tensor-bearing shards as auxiliary replay — **those rows get zero normal IQL sample weight and only contribute margin losses, so they never behavior-clone the avoided action.** `--pairwise-data-min-reward-gap` filters them by `pairwise_reward_delta_targets`; `--pairwise-reward-delta-weight`/`--pairwise-reward-delta-margin-scale` make the loss tail-aware by scaling row weight and required margin with the counterfactual reward gap.
  - **Regularizers**: `--policy-kl-anchor-checkpoint` + `--policy-kl-weight` regularizes the trained masked policy toward a frozen anchor — the preferred safety control before retrying policy-side branch-CF distillation. `--external-risk-checkpoint` + `--external-risk-policy-weight` uses a frozen action-risk critic as a policy regularizer; prefer family-scoped first runs such as `--external-risk-policy-family discard`.
- **scripts/train_offline_q.py** (`fh-mj-train-offline-q`) — Conservative masked-action offline Q-learning with optional BC warm-start.
- **scripts/train_global_ev.py** (`fh-mj-train-global-ev`) — Train the visible-state global EV predictor on transition shards, using final acting-seat terminal reward as the label and reporting validation MAE/RMSE/correlation against a train-mean baseline. `--reward-shaping placement` trains on rank-based placement EV. `--action-conditioned` trains `EV(state, action_id)`, required for same-state first-divergence guard/rerank diagnostics. `--branch-cf-action-targets` expands exact branch-CF preferred/avoided rewards into action-conditioned targets; `--branch-cf-pairwise-weight` adds an explicit preferred-above-avoided margin loss (use after branch reward regression ranks exact labels but still fails paired-trace guard preflight).
- **scripts/train_pairwise_delta.py** (`fh-mj-train-pairwise-delta`) — Train the direct paired-trace reward-delta predictor from one or more train reports and evaluate named report splits. Diagnostic-only until it passes holdout-only paired-trace preflight; prefer it over more action-EV coefficient sweeps when absolute action values fail cross-window holdouts. `--sequence-model` uses the visible pre-divergence sequence encoder and should be compared against the scalar/action MLP on source-heldout reports before any promotion attempt. `--source-balanced-batches`/`--worst-source-loss-weight` are for source-robust experiments after a model passes one heldout source window but fails a fresh one — **use them to change the training objective, not to tune serving thresholds.**
- **scripts/train_branch_preference_policy.py** (`fh-mj-train-branch-preference-policy`) — Train policy/Q heads to put exact branch-CF preferred actions into the checkpoint's top-k proposals. Initializes from an anchor checkpoint, freezes the shared encoder by default, supports anchor KL regularization. Use after targeted branch-CF diagnostics show the candidate rarely proposes exact preferred branches.
- **scripts/train_action_risk.py** (`fh-mj-train-action-risk`) — Train action-conditioned large-loss risk heads from saved transition shards with balanced positive/negative batches. Use as a calibration-only path when IQL auxiliary training is active but large-loss AUC remains near random; it optimizes the observed dataset action's risk probability and severity directly.
  - `--paired-trace-report` adds counterfactual first-divergence supervision (the risk head must rank the worse candidate above the anchor and fit the reward-delta severity target on matched rows); `--paired-trace-counterfactual-labels` broadens from large-loss/worst-delta cases to all first-divergence gaps above `--paired-trace-min-reward-gap` — **run a match-count smoke first, shard coverage can be sparse.**
  - `--target-mode` variants, in the order they were tried: `score_pressure` (expands the terminal large-loss target with visible Chongci match-pressure context from scalars 42-57); `discard_later_pressure` (terminal labels plus positives for discards followed by same-seat visible pressure within `--discard-later-window`); `discard_future_outcome` (avoids pressure proxies — positives for recent same-seat discards before actual bad terminal outcomes); `future_outcome_context` (labels recent same-seat actions before bad outcomes, scaling credit by visible score pressure plus action family); `family_future_outcome_context` (separates discard hindsight from chii/pon/kan/pass/haitei hindsight).
  - `--family-balance-strength`/`--family-weight-clip` apply optional action-family-balanced loss weights while preserving stored `sample_weights`, so discard-heavy datasets don't fully dominate calibration.

### Scripts — evaluation and gating

- **scripts/evaluate.py** (`fh-mj-evaluate`) — Evaluate a checkpoint offline (action agreement) and/or online (live play). Offline inference is batched; tune `--offline-batch-size` for GPU memory/throughput. `--match-mode chongci` forwards Chongci settings into online and duplicate-seat evaluation.
  - **Decision-cap default**: when `--max-steps-per-episode` is unset, the bridge cap defaults per mode — 256 (classic, via `EnvConfig`) or 4000 (chongci, matching `fh-mj-train-ppo`). A full chongci match needs ~1500 decisions, so the classic 256 default would truncate every match; the per-mode default lets matches reach `PHASE_MATCH_END` and report real standings. An explicit flag always wins.
  - `--sample-temperature T --sample-top-k K --sample-action-family F --sample-seed S` (requires `--duplicate-seats`) routes decisions through the SERVING sampler (`CheckpointPolicy` via `policies.SampledServingPolicy`), so a deployment temperature sweep measures exactly what production ships; seeded per seat, config recorded under `report["sampling"]`. Default `T=0` keeps the greedy model path byte-identical.
  - `--search [--search-determinizations K --search-max-candidates M --search-prior-mass P --search-max-rollout-decisions R --search-seed S]` (requires `--duplicate-seats`; numeric `--search-*` flags require `--search`; incompatible with `--sample-temperature > 0` and with an oracle eval env, i.e. `--oracle` without `--from-oracle` — the Go search pool rejects oracle observations, so the CLI fails loudly instead of deep in the run) routes decisions through `SearchPolicy`: a fresh per-seat greedy `CheckpointPolicy` (no sampling kwargs) plus a `pool_factory` building `GoSearchPool` over that seat's own live bridge. Seat seeds derive as `search_seed*4+seat`, mirroring the sampling path. Search config + `fallback_count` summed over seats is recorded under `report["search"]`, present ONLY when `--search` is active.
  - `--model-growth-blocks N` (deep16-rezero) and `--model-event-hidden-dim`/`--model-event-output-dim` (gru-width) are the explicit-flag paths for architecture recovery — usually redundant with checkpoint metadata (`infer_model_config` recovers `growth_blocks` from `growth.{i}.alpha` key presence and `event_output_dim` from `event_encoder.output_proj.weight`'s shape) but load-bearing when metadata is absent or an override is deliberate. All flow into report/MLflow provenance so a screening/confirmation report records the architecture it was produced against.
- **scripts/compare_reports.py** (`fh-mj-compare`) — Seed-clustered paired diff of two duplicate-seat report JSONs (`--json` for machine-readable output); refuses to compare reports whose seed lists don't match. **This is the required tool for any promotion/gate-verdict claim — read the clustered CI, not the naive one.**
  - **Seed windows (binding)**: screening runs use `--start-seed 910000` (cheap, unlimited, never cited for promotion). Confirmation runs — the only ones that may back a promotion or lever verdict — use a **fresh window no prior lap has spent**, 1500 seeds/side, pre-registered before launch. A confirmation window burns once and is then retired; reusing one carries winner's-curse bias. Spent so far: `870000+`, `950000+`, `990000+`, `1030000+`, `1070000+`, `1110000+`, `1150000+`, `1190000+`. See `worklog/rl-experiment/chongci-rl-experiment-progress.md` for the power reference.
- **scripts/benchmark.py** (`fh-mj-benchmark`) — Benchmark a checkpoint vs 3 heuristic bots with seat rotation (the policy plays every seat 0-3 over disjoint seed ranges from `--seed-base`); reports Tenhou-style per-hand stats (win/deal-in/draw rate, avg win value, avg deal-in loss) pooled across all seats plus match-level bootstrap CIs (`hand_stats`), alongside a per-seat breakdown. Loads via `CheckpointPolicy.from_checkpoint` (metadata-driven architecture recovery incl. `event_window`) and serves greedily via `TorchGreedyPolicy`. **This is an absolute-strength YARDSTICK, not a gate** — the heuristic bots are far weaker than the champion, so it must never be wired into the selfplay loop or promotion path. Writes `<checkpoint>.benchmark.json` (override with `--out`) plus a stat table to stdout.
- **scripts/evaluate_risk_guarded.py** (`fh-mj-evaluate-risk-guarded`) — Evaluate an action-risk checkpoint as a conservative guard around a promoted anchor policy, sweeping anchor-risk thresholds while preserving Go legality validation. `--selection-mode policy_topk_risk --policy-top-k N` reranks only the anchor's top-N legal actions by risk — the live counterpart to branch-CF proposal/rerank diagnostics.
- **scripts/reward_calibration.py** (`fh-mj-reward-calibration`) — Report Q/value calibration against discounted terminal payout targets before promoting reward-trained checkpoints. `--large-loss-threshold` enables auxiliary large-loss metrics (probability Brier/AUC, severity error); `--large-loss-risk-mode` can force action-conditioned or legacy state-only calibration.
- **scripts/evaluate_q_guarded.py** (no console entry) — Evaluate a candidate reward/Q checkpoint behind a promoted anchor policy, sweeping one or more minimum Q-margin thresholds.
- **scripts/evaluate_tail_constrained.py** (no console entry) — Evaluate a reward-trained candidate behind an anchor with an explicit no-worse-large-loss-risk constraint from an action-risk model. Use after pairwise-margin IQL improves EV but regresses tail risk.

### Scripts — serving and benchmarking

- **scripts/serve_policy.py** (`fh-mj-serve-policy`) — Lightweight JSON HTTP policy server. It returns an `action_id`; **callers must still apply Go-side action decoding/validation before mutating game state.**
  - **`POST /act`** response: `{"action_id", "value", "value_calibrated", "checkpoint_path", "checkpoint_step", "checkpoint_sha256"}`. The `checkpoint_sha256` field (paipu v2, `worklog/specs/2026-08-09-paipu-v2-provenance-design.md` §4) is sourced from ONE `self.holder.snapshot` captured before `policy.choose()` runs — the same atomic `(policy, checkpoint_sha256)` pair pattern `/evaluate` uses — so a concurrent `/reload` between the read and the response can never attest a different checkpoint's hash for this action. Go's `internal/bot/remote.HTTPPolicy` decodes it into per-decision `bot.DecisionProvenance.CheckpointSha` (empty string on a legacy server that predates the field — never an error).
  - **`POST /evaluate`** `{"observations": [{"seat", "planes", "scalars", "action_mask"}]}` batches `CheckpointPolicy.evaluate_batch` for the Go post-game review pipeline (`internal/review/client.go`). Response `{"results": [{"probs": [204 floats], "value": float}, ...], "checkpoint_path", "checkpoint_step"}`, results in request order, `probs` dense length-204 with exact zeros on illegal actions, deterministic regardless of the server's `--sample-*` flags. Requests over `MAX_EVALUATE_BATCH` (1024) are rejected 400 (the Go client chunks at 256 so it never trips this). An observation whose `action_mask` has no legal action is also rejected 400 instead of returning NaN probs.
  - **`/evaluate` authentication (adversarial round 19)** — `/evaluate` is disabled ENTIRELY unless launched with `--evaluate-token TOKEN` (or `FH_MJ_EVALUATE_TOKEN`); an unauthenticated `/evaluate` would return dense per-action probability vectors for up to 1024 caller-controlled observations per request, a model-extraction surface (logit differences recoverable from `log(p_i/p_j)`) and compute-DoS path that made the `/act` `--logit-export-token` gate moot on any public deployment. With no token, every request gets 403 BEFORE the body is read or `evaluate_batch` runs. With a token, requests must carry `Authorization: Bearer <token>` (`hmac.compare_digest`, checked before the body is read). **Unlike `--logit-export-token`/`--admin-token`, this token is required in production** — review runs against the production serving instance. Go sends the matching header via `internal/review.NewHTTPPolicyClientWithToken`, wired from `POLICY_SERVER_TOKEN` in `internal/api/review.go`.
  - **`GET /healthz`** reports `checkpoint_sha256` (sha256 of the checkpoint file, computed once at load and again after any successful reload — never per request), `model_config` (full `dataclasses.asdict(ModelConfig)`), `event_window`, `contract_version` (`EVENT_CONTRACT_V1`), and the active sampling config.
  - **`POST /reload`** fully validates the NEW checkpoint (load, metadata cross-check via `infer_model_config`, event-window compatibility) BEFORE swapping the reference — `PolicyHolder.reload` compares the new checkpoint's `event_window` against the CURRENTLY-serving policy's window and raises (leaving the old policy serving, 400 response) on mismatch. Pass `"expected_event_window": N` to deliberately promote across a window change (e.g. champion → first event-window checkpoint). A reload PRESERVES the sampling config — a hot-swap never silently reverts to greedy.
  - **`POST /warmup`** takes a genuine forward pass so no in-match `/act` pays the cold-start cost. Driven by Go's `remote.WarmupManager`; see `internal/bot/remote/CLAUDE.md`.
  - **Spec B2c event contract** (`observation_from_json(payload, model_event_window)`, shared by `/act` and per-row `/evaluate` parsing): `model_event_window` is the serving model's `ModelConfig.event_window` (0 = event-free champion, read fresh off `policy.model.model_config` on every request so a reload takes effect immediately). Window-0 models IGNORE `event_history`/`event_count`/`event_window`/`contract_version` entirely — regression bar, byte-identical to pre-B2c behavior even if a caller sends garbage in those fields. Event models (window > 0) REQUIRE `event_count`/`event_window`/`contract_version` on every observation (Go always sends the three scalars; `event_history` itself may be omitted only when `event_count == 0`, since Go's `omitempty` drops the empty array — treated as `[]`). 400 on: `len(event_history) != event_count`, `event_count > event_window`, `event_window != model_event_window`, or `contract_version != EVENT_CONTRACT_V1`. `event_count == 0` with otherwise-consistent fields is valid (early round) at this layer — `CheckpointPolicy.choose`'s own empty-history guard is what then rejects it, surfacing as the same 400 style as every other `/act` exception.
- **scripts/reload_policy.py** (`fh-mj-reload-policy`) — Thin HTTP client to hot-swap or inspect the model served by a running policy server. The *server* loads the checkpoint into the live model, so switching needs no restart of the policy server or the Go backend. **No torch import, so it starts instantly.** `--status` shows the current model; `--checkpoint PATH` switches.
- **scripts/serving_smoke.py** (`fh-mj-serving-smoke`) — Load a manifest checkpoint and step through the mock or Go bridge so legality validation catches invalid served actions.
- **scripts/serving_parity.py** (`fh-mj-serving-parity`) — Spec B2c Task 8: the **HARD-GATE eval-vs-serving action parity harness — the runbook's promotion gate, not a smoke test.** For every seeded bridge decision state it builds the exact `/act`-shaped JSON payload `HTTPPolicy.chooseRemoteCtx` would send (`build_act_payload`; field names mirror `internal/bot/remote/http_policy.go`'s `actRequest`, event history tail-windowed to the checkpoint's own `event_window`), then compares two independent code paths against the SAME loaded checkpoint: the "reference" path (`TorchGreedyPolicy.choose()` fed the raw bridge `Observation` directly) vs the "serving" path (`observation_from_json` decode then `CheckpointPolicy.choose()` — `--in-process`, fast/CI-safe — or a real HTTP POST to a running server — `--endpoint URL`, the actual hard gate against a prod image).
  - In `--endpoint` mode, before any decision is checked, `verify_endpoint_checkpoint_identity(endpoint, checkpoint)` GETs `/healthz` (URL derived from `/act` the same way `internal/bot/remote/health.go`'s `deriveHealthURL` does) and compares the reported `checkpoint_sha256` against the sha256 of `--checkpoint`; a mismatch raises `ServingParityError` immediately — **an endpoint quietly serving a different checkpoint must never look like a clean parity pass.** An older server whose `/healthz` omits the field is allowed to proceed with a `WARNING` on stderr.
  - Any action-id mismatch, illegal action, HTTP/decode error, or (in-process only) masked-logit max-abs diff over `1e-4` is an immediate `ServingParityError` dumping the seed, decision index, and state summary. `main()` exits 0 only when every decision checked agreed — `ParityReport.all_agree` is explicitly **vacuity-proof: zero decisions checked is a fail, not a pass.**
  - Flags: `--checkpoint`, `--event-history-window`, `--episodes`, `--start-seed`, exactly one of `--in-process`/`--endpoint`, plus `--device`/`--bridge-kind`/`--bridge-lib`/`--max-decisions`/`--http-timeout`.
- **scripts/collect_bench.py** (`fh-mj-collect-bench`) — Exact-semantics worker-count benchmark that gates `--num-workers` choices before a real multi-day `train_b2b` lap. For every requested count it constructs the ACTUAL persistent, spawn-context `ParallelB2bCollector`, includes pool startup plus one warmup collection in `startup_seconds`, then reuses those workers for one digest-bearing steady collection reported as `steady_seconds`. The canonical sha256 covers seed context and every `RolloutBatch` field (including PPO-critical `dones`, `values`, `old_logprobs`) with each array's shape/dtype, and **fails closed if a future batch field is not enumerated.** `--champion CKPT [--model-growth-blocks N]` selects the growth or 39ch-surgery warm-start path, matching `train_b2b`'s dispatch.
  - **Adoption rule: pick the fastest worker count whose digest exactly matches the smallest/reference count.** Exits 0 iff `all_digests_equal` (and with `--full-cycle`, `rows_and_labels_equal` too), and groups mismatching counts by digest.
  - **Scope note**: collection is CPU-bound regardless of `--device` (mirrors the real multi-worker production path, which hardcodes CPU per worker); it does not cover `train_b2b`'s `--num-workers 1` direct device path. Spawn-safe perturbation tests use a narrowly named environment-gated worker hook because parent monkeypatch state cannot survive spawn.
  - `--full-cycle` (data-scale-960 Stage 0 preflight) extends each phase into a complete training iteration: after the steady collection it runs GAE + one real `ppo_update` on a fresh deep copy of the warm-started model (fresh optimizer, fixed `--update-seed`, so the update is identical across worker counts) at the recipe hyperparameters (`--minibatch-size`/`--ppo-epochs`/`--gamma`/`--gae-lambda`/`--lr`/`--entropy-coef`/`--ppo-device`), and reports per worker count: host peak RSS over the whole collect+update phase (Linux `/proc` tree sampler; `getrusage` lifetime fallback elsewhere), CUDA peak allocated/reserved, transition rows, optimizer steps, matches/s, `dealin_positive_rate`/`rank_label_coverage`, truncation, aggregated KL and clip fraction — **the memory-honest preflight for raising `matches_per_iter`** (`ppo_update` puts the entire rollout on the update device).
  - `--dispatch-chunk N` (Amendment 2) threads `PPOConfig.collect_dispatch_chunk` into the collector: bounded sequential dispatch rounds of ≤N matches (contiguous ascending seed blocks) that bound per-worker resident trajectory memory at ~N/workers matches — the single-dispatch path made every worker hold its whole matches/workers block, which OOM'd the 31GB box at 960 matches. Chunking is bit-identical to single dispatch (per-match seeding; chunk-parity digest tests) and recorded as `dispatch_chunk_matches`.
  - `--minibatch-device-transfer` (Amendment 5) runs the `--full-cycle` update with the rollout host-resident, moving each minibatch to `--ppo-device`. Amendment 5 also has `ParallelB2bCollector` close its worker pool after the final dispatch's results arrive and before remaining concatenation (~1.8GiB/worker freed ahead of the concat transient), auto-restarting on the next collect — so a second collect spans a pool respawn (~1min), included in its timing.
  - Runbooks: `worklog/plans/2026-07-24-deep16-rezero-runbook.md`, `worklog/plans/2026-08-12-data-scale-960-runbook.md`.
- **scripts/collect_profile.py** (`fh-mj-collect-profile`) — Measurement-only memory profile of the UNCHANGED collection + update path (data-scale-960 Amendment 4), authorized after the Amendment 3 preflight's master OOM'd at 33.8GiB anon-RSS (~3x one dataset copy).
