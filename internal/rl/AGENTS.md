# internal/rl/

> Deterministic RL environment wrapper around the Go game engine.

## Overview

This package keeps the authoritative simulator in Go while exposing a training-oriented interface: fixed action ids, seat-relative observations, deterministic seeded resets, step-to-next-decision flow control, and heuristic trajectory export.

## Key Files

- **action.go** — 204-action catalog plus action-mask generation and action encode/decode helpers. `DecodeActionID` is exported so serving clients can validate remote policy ids through the same legality map used by the RL bridge. `LegalActions` and `EncodeAction` are thin exported wrappers around the already-private `legalActionMap`/`encodeAction`, added so `internal/review`'s paipu replay driver resolves recorded actions through the exact same legality map the RL bridge uses instead of re-deriving it.
- **observation.go** — Seat-relative observation encoder (`39 x 42 x 1` planes, 58 scalars) with no hidden-opponent tile leakage. `EncodeObservation` is exported for remote-policy clients that need the same visible input format as Python training; it always passes `nil, 0` for the internal event-history params, so exported callers (`internal/review`, `internal/bot/remote`) never see event history and stay dormant/byte-identical. The internal `encodeObservation` additionally takes `events []engine.PublicEvent, window uint32` and appends `EventHistory`/`EventHistoryWindow` to the returned `SeatObservation` via `renderEventHistory` (see `eventcodec.go`). `emptyObservation` and `cloneObservation` carry `EventHistoryWindow`/`EventHistory` through too, so a dropped-observation path or a pool clone never silently loses event history.
  - `publicSeenCounts` intentionally excludes `state.ActiveDiscard`: the claimable discard is already present in the discarder's `Discards` during claim windows, so also summing `ActiveDiscard` double-counted that tile. Fixed 2026-07-14; regression-tested in `observation_test.go`.
- **eventcodec.go** — Owns the packed public-event bit layout (`type | rel_seat<<4 | face<<6 | rel_from<<12 | tsumogiri<<14 | haitei<<15`, bits 16-31 reserved and always zero) mirrored verbatim in `ai/src/fh_mahjong_ai/events.py` — change BOTH files or neither; the golden vector in `eventcodec_test.go` is shared byte-for-byte with `ai/tests/test_events.py`. `packPublicEvent(event, observer)` renders one `engine.PublicEvent` observer-relative and enforces information legality AT ENCODE TIME: a DRAW's face is masked to `EventFaceUnknown` (63) unless the observer is the drawing seat — the engine log itself always stores true faces. `renderEventHistory(events, observer, window)` renders the last `window` events oldest-first and returns `nil` at `window == 0` (dormant — the observation stays byte-identical to pre-B1, tested by `TestDormantWindowByteParity`).
  - **eventcodec_test.go** — Golden bit-layout vector + relative-seat/truncation-order unit tests, plus behavioral tests over full seeded random matches: dormant byte-parity at window 0, information-legality (own-draw visible, opponent-draw masked, no reserved bits) over a full match, a paipu-record cross-check (event log vs recorder actions for one round), a tsumogiri-flag capture invariant (every flagged discard's most recent preceding draw is by the same seat, and both flagged/unflagged paths are exercised), and clone/search consistency (`CloneForBranch` inherits the log; clone appends never leak into the parent).
- **env.go** — `Env` wrapper with deterministic `Reset`, `Step`, `EvaluateBranches`, and `GenerateHeuristicTrajectory`.
  - Terminal responses include `RoundOutcome` metadata for winner, win type, discarder, draw flag, score, and payouts.
  - In Chongci mode, `Env.Step` / `advanceToDecision` returns a dense per-step reward from `scoreDeltaReward`: the acting seat's running-score delta since the previous decision, which telescopes exactly to the match net-change.
  - `EvaluateBranches` clones the live `engine.Game`, applies each candidate action from the current learning-seat decision, then lets deterministic heuristics finish the branch to create same-state counterfactual labels without mutating the live environment.
  - Branch requests can stop at the next round end for multi-hand modes, returning hand payout labels from the current visible match context instead of rolling every candidate to full Chongci match end.
- **envpool.go** — `EnvPool`: `slots` independent envs stepped in lockstep rounds via `ApplyCommands` (one command per slot per call: step/reset/skip; commanded slots run concurrently in goroutines). Returns flat little-endian float32/uint8 observation buffers (rows = has_observation slots, ascending slot order) plus per-slot `SlotState` metadata. Never self-resets — the foreign caller owns the seed schedule. `appendObservationRow` packs one obs into the flat buffers and seeds the header dims on the first row; it is shared with `SearchPool` so both pools emit an identical flat layout. When `event_history_window > 0` each row also carries a uint32 LE count plus a fixed-width (window-stride) tail-padded event row — the explicit count exists because packed `0x0` is a VALID event, so padding alone is ambiguous; all three event fields are empty at window 0 (dormant).
- **searchpool.go** — `SearchPool`: K determinized clones of ONE live `Env` decision point for test-time search (Python rollout/MCTS loop). `NewSearchPool(e, clones, seed, maxRolloutDecisions, determinizations, [rootSeat])` builds each clone as `e.game.CloneForBranch()` + `RedealUnseen(actingSeat, redealSeed)`, wrapped in a fresh `Env` (all four seats learning, `decisionCount` copied, `lastScores` seeded from the clone's visible scores so dense per-step rewards measure change since the branch point). Rejects a nil env, an oracle-configured env (search must never see oracle channels), or an env not at a decision point. `Step` reuses the `EnvPool` proto messages: `action_id` steps a clone, `skip` idles it, `reset_seed` is a per-slot error (`"search pool has no reset"`). `Close()` drops the clones.
  - **Explicit root seat (duplicate-seat-eval correctness)**: the variadic `rootSeat` makes the search root EXPLICIT. When supplied it is validated against `Env.seatHasPendingDecision(seat)` (the per-seat form of `currentActionSeat`) and used as the pool root; when omitted the pool falls back to `currentActionSeat()` (the all-four-learning self-play default — existing Go tests pass no root and rely on this). The explicit form is REQUIRED under duplicate-seat evaluation (`auto_play_heuristics=true`, one learning seat): at a WAIT_DISCARDS window a lower-numbered heuristic opponent can hold an unqueued interrupt at the same time as the learning seat, so `currentActionSeat()` returns the opponent and an implicitly-rooted pool would protect the WRONG hand across `RedealUnseen` and pin the candidate id to that opponent (mis-score or fail-open at interrupt decisions). Proto `SearchPoolNewRequest.root_seat` is proto3 `optional` (seat 0 ≠ absent, per the tile-id-0 lesson); the FFI passes it through only when present. Python `GoSearchPool(..., root_seat=…)` and `SearchPolicy` (which passes `root_seat=observation.seat` through `pool_factory`) wire it end-to-end. Verified by `TestSearchPool_ExplicitRootSeatUnderDuplicateEval`.
  - **Common-random-numbers pairing + no-live-seed guarantee (honesty-critical)**: `determinizations` is the pairing group count K (the clone count is M candidates × K). Clone `i` belongs to group `k = i % K` (K=0 ⇒ K:=clone count, so every clone is independent). BOTH per-clone seeds are derived from `(pool seed, k)` ALONE — `redealSeed = seed*1_000_003 + k` (the redealt hidden world) and the clone `Env.baseSeed = seed*7_919 + k + 1` (which seeds the NEXT hand's wall at a Chongci round boundary via `deriveHandSeed`). **Neither is ever derived from the live `e.baseSeed`.** Copying the live env's `baseSeed` (the pre-fix bug) let a rollout crossing a round boundary deal the live simulator's ACTUAL future hand, and the root-seat next-hand bootstrap obs then contained the player's real future tiles — information unavailable at the root decision. Deriving from `(seed, k)` means clones `(c,k)` and `(c',k)` in different candidate groups share a byte-identical determinized world AND identical sampled future, so candidates are compared on paired worlds (variance reduction) and the live future is never consulted. Verified by `TestSearchPool_PairedDeterminizationsShareWorld` (paired clones share, distinct k differ) and `TestSearchPool_CloneWorldIndependentOfLiveSeed` (identical state but different live `baseSeed` ⇒ identical clone rollout). The Python `GoSearchPool.__init__`/`SearchPolicy` pass K through as `determinizations=K` (clone count `len(candidates)*K`).
  - **Response-contract deviations** (all within `SlotState`, vs `EnvPool`/FHEnvPool): (1) `RoundOutcome != nil && !Terminated` ⇒ a ROUND ended earlier in the rollout and the clone has now reached the **ROOT seat's next GENUINE decision**, whose observation (real decision state, real mask) is the value-bootstrap row with the captured outcome attached; Python scores `step_rewards[root] + V(row)` and skips the clone. Between the boundary and this row the clone surfaces ordinary live-decision rows for the OTHER seats (no outcome) which Python steps with the champion. (2) `Terminated=true` ⇒ match end, `HasObservation=false` (dense rewards already telescoped the outcome), but `RoundOutcome` IS attached (the latest captured pending outcome, or the current round's, nil-safe) so callers still get final-round payout metadata — symmetric with the classic-terminal path; if the match ends while still awaiting a bootstrap, there is NO bootstrap obs (GAE terminal convention). (3) `Truncated=true` (per-clone decision cap, checked ONLY at a root decision) ⇒ `HasObservation=true` — the cap-state observation IS returned, and it is always a genuine root decision state (unlike `EnvPool`'s assembler, which drops the obs on truncation). `assembleSearchResponse` implements this looser inclusion rule.
  - **Bootstrap rows are IN-DISTRIBUTION root decisions, never a frozen foreign-turn view.** The champion value head was trained on per-seat GAE where V is only evaluated where THAT seat has a genuine decision. So a round boundary does NOT stop the clone: `advanceClone` captures the outcome, sets `searchClone.awaitingBootstrap` + `pendingOutcome` (both persist across `Step` calls), and keeps surfacing ordinary rows until acting seat == `p.rootSeat`, then emits THAT row (real mask) as the bootstrap with the outcome attached. A second boundary while awaiting carries the LATEST outcome; a match end while awaiting ⇒ terminated (latest outcome as metadata, no obs). This replaces the old "root's view frozen at the next hand's start" row, whose empty mask + candidate-dependent OOD error (Chongci dealer succession) corrupted candidate ranking. Only ordinary live-decision rows encode the current acting seat and drive rollout.
  - **Decision cap + hard safety stop**: the per-clone `maxRolloutDecisions` cap is checked ONLY when the surfaced decision's acting seat == `p.rootSeat`, so a truncation row is always a genuine (in-distribution) root decision state. A hard safety stop fires a per-slot error once total `clone.decisions >= 2*maxRolloutDecisions+16` with no root decision reached, so a pathological no-root-decision loop cannot spin (Python fail-open drops the errored clone).
  - **Round-end detection**: `advanceClone` captures `roundOutcome(state)` at `PHASE_ROUND_END` BEFORE readying up, because Chongci's `startNextRound()` nils `State.RoundResult`; relying on a post-advance HandNum change would lose the payout data. It arms the bootstrap and continues; the outcome is attached to the eventual root-decision bootstrap row (or, if the match ends first, to the terminal `SlotState`).
  - **WAIT_DISCARDS interrupt re-ask (cross-task contract)**: `RedealUnseen` clears the clone's interrupt queue AND refreshes each non-acting seat's `ValidActions` against its reshuffled hand, so a pool created at a WAIT_DISCARDS point where a seat had already queued a response re-asks every interrupt-window seat as a policy decision (all four seats are learning) with executable, non-stale interrupts; the window is never silently resolved for a previously-queued seat, and a surfaced meld interrupt is guaranteed to apply cleanly (no phantom open meld / duplicate tile ids). Verified by `TestSearchPool_InterruptWindowReAsked` (re-ask) and `TestSearchPool_InterruptWindowExecutable` (step-and-consistency).
  - **Root-action pinning (WAIT_DISCARDS-root correctness)**: the FIRST `action_id` command a clone receives is the ROOT CANDIDATE — the move being searched for `p.rootSeat` — and is decoded/executed for `p.rootSeat`, NOT for `currentActionSeat()` (`searchClone.rootApplied` gates this). This matters because `RedealUnseen` recomputes interrupt eligibility for EVERY opponent, so at a WAIT_DISCARDS root a clone's first `currentActionSeat()` can be a newly-eligible LOWER-numbered seat rather than the root; `ProcessPlayerAction` in WAIT_DISCARDS accepts interrupt responses from any window seat asynchronously (`handleInterruptAction`), so pinning plays the candidate as the root's move (and a Pon action id is face-based/seat-independent, so a mis-pinned candidate would legally execute as the WRONG seat's move — the corruption this prevents). At a PLAYER_TURN root `currentActionSeat() == rootSeat`, so pinning is a no-op. Every SUBSEQUENT command uses `currentActionSeat()` (the other window seats' responses, later turns). Verified by `TestSearchPool_RootActionPinnedToRootSeat` (root candidate queued for the root seat; newly-eligible lower seat surfaced as an ordinary decision afterward).
- **action_test.go** — Fixed action/tile-index mapping tests; tile faces follow the backend shanten order `man, pin, sou, jihai, flower`.
- **env_test.go** — Determinism, action round-trip, hidden-information, and trajectory-export tests.
- **searchpool_test.go** — SearchPool honesty invariant (acting-seat obs identical across clones), opponent-hand variation, seed determinism, oracle/nil-env rejection, round-end-emits-next-hand-obs, the redesigned bootstrap-is-a-root-decision contract (`TestSearchPool_RoundEndBootstrapIsRootDecision`: after a boundary the clone surfaces foreign ordinary rows, then a bootstrap row with seat == root + a NON-EMPTY mask + the captured outcome), match-end-while-awaiting (`TestSearchPool_MatchEndAttachesOutcome`: terminated, outcome attached, no obs), root-gated decision cap + hard safety stop (`TestSearchPool_DecisionCapTruncatesAtRootDecision`, `TestSearchPool_HardStopOnNoRootDecision`), reset-is-per-slot-error, the WAIT_DISCARDS interrupt re-ask contract, the interrupt-window executable/no-corruption contract (`TestSearchPool_InterruptWindowExecutable`), root-action pinning at a WAIT_DISCARDS root (`TestSearchPool_RootActionPinnedToRootSeat`), CRN determinization pairing (`TestSearchPool_PairedDeterminizationsShareWorld`), and clone-world independence from the live `baseSeed` (`TestSearchPool_CloneWorldIndependentOfLiveSeed`).
- **kan_dup_repro_test.go** — Fuzzes random self-play and asserts the engine's wall-consumption invariant: no tile id ever appears twice in any hand (and no unexpected step error). Regression gate for the dead-wall/front double-draw bug that surfaced as a `duplicate action id ... ACTION_KAN` crash.

## Architecture Notes

- `internal/rl/` wraps `engine.Game`; it must not fork rules or state-transition logic.
- Non-learning seats are automated through the shared Go heuristic bot when `auto_play_heuristics` is enabled.
- `EnvConfig.match_mode = MATCH_MODE_CHONGCI` starts the core engine with Chongci options and treats `PHASE_MATCH_END` as the terminal RL state.
- During Chongci generation/evaluation, `advanceToDecision()` auto-acks `ROUND_END` ready gates so an episode can span multiple hands until bust or hand cap.
- Chongci `Reset(seed)` derives a deterministic wall seed for each later hand before the final ready ack starts the next round; same episode seed plus same policy must replay the same multi-hand match.
- Chongci terminal rewards are final score net change divided by 1000, matching the scale of classic single-hand payout rewards.
- Classic mode rewards are unchanged: intermediate `Score` stays 0 and round end still returns `roundRewards`.
- `advanceToDecision()` only resolves WAIT_DISCARDS automatically after verifying every pending interrupt seat has already queued a response; otherwise it returns an error instead of silently skipping input.
- `advanceToDecision()` must resolve an already-ready WAIT_DISCARDS window even when `AutoPlayHeuristics` is disabled, because all-four-seat heuristic trajectory export records each seat as a learning seat and can otherwise stall after queued interrupt responses.
- Tile-face indices in observations and tile-specific action ids use the same order as the rules/shanten backend: `man(0-8), pin(9-17), sou(18-26), jihai(27-33), flower(34-41)`.
- Scalar features include overall and route-specific shanten, ukeire, discard look-ahead, wild preservation, visible score potential, and public danger heuristics.
- Scalar indices 42-57 carry Chongci/match-context features: mode flag, hand progress, remaining hand fraction, rank strength, leader pressure, large-loss safety margin, own bust safety, opponent large-loss pressure, normalized score/net progress, relative score gaps, next-rank pressure, lower-rank cushion, and public current-hand threat.
- Heuristic trajectory export keeps immediate step rewards in `TrajectorySample.rewards` and stores final payouts/outcomes separately in `TrajectorySample.terminal_rewards` and `TrajectorySample.terminal_outcome`; Chongci `GenerateHeuristicTrajectory` keeps each sample's `TerminalRewards` equal to `matchEndRewards`, so offline return-shaping remains match net-change based.
- Branch evaluation through `advanceToTerminalWithHeuristics` is unchanged by Chongci dense per-step rewards.
- `FLOWER_REVEAL` is treated as a system action and is intentionally excluded from the agent action space.
- Tile-type keys, the 0-33 index, and proto Tile/Action deep-clones come from the shared `tiles` package (`github.com/plasma/fh-mahjong/internal/tiles`) — do not re-inline `suit*100+value` or re-add local `cloneTile`/`cloneAction`.
