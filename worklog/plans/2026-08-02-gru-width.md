# GRU-Width Lap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Function-preserving event-GRU widening (128→256 hidden, identity-masked 256→128 output projection) so the ratified ~165-iteration sequence-core lap can launch against restart-iter075.

**Architecture:** `event_output_dim` is a dormant-at-0 ModelConfig field (0 ⇒ no projection module ⇒ state_dict byte-identical). `EventEncoder.output_proj` exists only when set; every event-feature-width derivation becomes `event_output_dim or event_hidden_dim`. `widen_event_gru` copies the anchor verbatim except the GRU (old rows copied, old←new recurrent blocks ZEROED, new rows free) and the `[I|0]` projection.

**Tech Stack:** Python 3.12, ai/ only. Spec: `worklog/specs/2026-08-02-gru-width-design.md` (§ refs below). Branch: `claude/gru-width` (spec commit f479ebc).

## Global Constraints

- `event_output_dim=0` ⇒ `state_dict()` keys byte-identical to today (test-proven).
- Step-zero invariant (binding): widened net's event features, policy logits, value, Q, aux outputs, greedy actions all `torch.equal` to the anchor's.
- The GRU surgery MUST zero the old-gate-rows × new-hidden-cols blocks of `weight_hh_l0` (per gate) — old-unit dynamics may not see new units. The parity test enforces this; the implementation must do it explicitly.
- `growth_blocks > 0` and `--widen-event-hidden > 0` together in one run ⇒ CLI error.
- Projection keys without usable metadata ⇒ fail-closed load (existing pattern).
- Full `uv run --project ai pytest -q` green per commit; commits end with: `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`
